# 跨环境落地指南与迁移注意事项

原插件依赖 WorkBuddy 专有的 `TeamCreate` / `Agent` 子代理工具和 `neodata-financial-search` 数据源。迁移到其他 AI 时按下面三种情况处理。

### 情况 1：目标 AI 支持子代理 / 多智能体（Claude Code、Cursor Agent、AutoGen、Dify 等）

按原样执行：主理人负责编排，把 12 个成员作为独立子代理调度。
- Phase 1 的 4 人、Phase 4 的 3 人**必须并行**，不得顺序串行（这是效率与"立场独立"的关键）。
- 子代理命名统一用 Agent ID（`market-analyst` 等），不要用中文名。
- 主理人只做编排与汇编，**不得代写任何成员的专业产出**。

### 情况 2：目标 AI 只有一个对话（ChatGPT 网页版、Gemini、DeepSeek 等）— 降级方案

让主模型**依次扮演**各角色，靠「产出标记」做阶段隔离：

1. 主模型先声明：`我现在开始 Phase 1，依次扮演 4 位分析师。`
2. 每扮演完一个角色，用方括号标记收尾并**换一次输出**（如 `[市场技术分析报告]`）。
3. Phase 1 四份报告全部产完后，主模型声明进入 Phase 2，扮演 `bull-researcher` → 产出 `Bull Analyst: [多头论证]`；再扮演 `bear-researcher`（**必须只基于多头的论点做针对性反驳，而不是重复一遍风险**）→ 产出 `Bear Analyst: [空头论证]`；再扮演 `research-manager` 裁决 → 产出 `[投资计划]`。
4. 依此类推走完 Phase 3、Phase 4。
5. 最后切回主理人身份，输出 Phase 5 报告。

**降级方案最大的失效点是「辩论会变成自说自话」**。缓解办法：在提示里强制要求——空头研究员必须逐条引用多头论点并反驳；三位风险分析师必须互相点名对方假设并挑战。角色扮演时也要让模型在每份产出开头显式写出「我现在的立场是 X」。

### 情况 3：数据源不可用

Codex 项目版配置了无需登录的 `akshare` MCP（中国股票）与 `yfinance` MCP（美国股票）。若其中一个当前不可用，使用公司/交易所/监管机构一手披露和公开网页行情作为替代，并在结果中说明来源与缺项。
- **保持单一口径**：同一指标不混用不同来源；数据冲突时以公司一手披露为准并写明。
- 所有数字标注来源和日期，拿不到写 `[MISSING]`，绝不编造。
- 技术指标（SMA/EMA/MACD/RSI/布林带/ATR）多数数据源只给价格，需按文档里的公式手工计算；如果目标 AI 能跑 Python，让它写脚本算，比心算可靠。

### 通用提醒

- 完整流程耗时较长（多轮子代理），**不要中途中断**。若目标 AI 有超时限制，改用 Workflow B 快速模式。
- 研究主管和风险主管**禁止以"双方都有道理"为由默认 HOLD**，必须给明确方向。
- 最终报告建议同时产出 Markdown 摘要 + 自包含 HTML 富媒体报告（Chart.js / ECharts），HTML 里禁止出现占位或虚构数据。

## 附：迁移时最容易丢失、但最影响输出质量的 8 条

1. **主理人不做分析** — 只编排、汇编、中转；任何专业产出必须由对应成员产出后采信。
2. **并行是硬要求** — Phase 1 四人与 Phase 4 三人的并行不只是为了快，更是为了让四个立场**互不知情**地独立形成。串行会污染独立性。
3. **所有跨成员信息流经主理人** — 成员之间不直连，避免立场互相传染。
4. **产出标记** — 每份产出用 `[市场技术分析报告]`、`Bull Analyst: [多头论证]` 这类方括号标记收尾，是阶段间准确引用的凭证。
5. **辩论要真打** — 空头必须逐条反驳多头论点；三位风险分析师必须互相点名挑战。走过场的辩论不如不辩。
6. **裁决必须果断** — 研究主管、风险主管不得默认 HOLD。
7. **数据源唯一 + 数字可追溯** — 缺失写 `[MISSING]`，禁止编造；这是整条链路可信度的基础。
8. **趋势判断不许模糊** — 技术分析师必须明确说"上涨/下跌/震荡"，禁用"趋势混合"这类和稀泥表述。

## 版本说明

原插件内部有两处口径不一致，导出时保留原文未改动，此处标注以便你按需统一：
- `plugin.json` 与专家定义为 **13 角色**（1 主理人 + 12 成员）；`trading-analysis` skill 正文写的是「11 个专业角色 Agent」，为旧版本遗留表述，以 **12 成员 + 1 主理人** 为准。
- 快速模式（Workflow B）在 skill 与专家定义中均注明跳过 Phase 2 与 Phase 4，两者一致。
