# 更深，而不是更大

将用户的原任务提升为一个更有依据、更可验证的版本，保持原本要解决的问题和交付边界。先回答四问，再给出可直接使用的改写提示词；**改写完成后停止，等待用户确认，不执行改写后的任务**。

## 确定对象与范围

- 以用户指定的任务、需求或功能为对象；显式调用时，以调用后提供的内容为准。未指定时，使用当前会话中最近明确的任务或刚完成的功能。对话中有多个可能对象且无法判断时，只询问要深化哪一个。
- 提炼原目标、对象、已有约束和预期交付物。保留用户明确的技术栈、兼容性、时限、隐私和权限要求；未知信息标为待确认，不凭空补充。
- “更深”指提高与原目标直接相关的事实依据、方法严谨性、边界处理或验证可信度；不默认新增功能、扩大受众或场景、重构相邻模块、增加交付物、开展大规模调研。必要的分析或验证步骤可以增加，但必须服务于原目标且与任务规模相称。
- 若某项建议会改变产品行为、接口、范围、成本或风险，将其作为可选项单列，不写成新要求。用户明确授权的范围变化除外。

## 四问

结合具体任务，简洁回答以下四项。区分已知事实、合理推断和待验证事项；证据不足时说明缺口，不把假设说成事实。

1. **专业补足**：该领域优秀从业者会做哪些用户尚未明确要求、但对原目标的正确性或质量关键的工作？只选最有价值的事项，说明它们如何服务原目标。
2. **原始材料**：优先指出最接近事实且可合法取得的材料，例如原始需求、实际代码、日志、数据、用户原话、协议或一手文档；根据任务选择，不假定材料存在或已经读取。现有摘要可作线索，不能冒充一手证据。无权访问或无法取得时写明，并提出最接近的可用替代品及其局限。
3. **方法与工具**：针对具体风险说明如何分析、使用哪些适用的方法或工具，以及它们各自回答什么问题。工具按环境可用性选择；避免空泛地说“深入分析”或罗列工具。按风险和成本取舍，不要求每个任务使用全部方法。
4. **独立验证**：提出不依赖助手或用户主观认可的可观察证据，如实际行为、可复现测试、原始数据对照、独立评审或权威规范。明确检查对象、通过标准或预期结果；区分已有证据与拟进行的验证。若没有绝对正确答案，采用与目标相符的可观察指标，并说明其局限。

## 改写与停止

- 将四问中真正必要的内容转化为一段独立、可复制的任务提示词：保留原目标和约束，明确材料、方法、验收证据及范围边界；将缺失信息写成条件或待确认项，不虚构路径、数据、结果或工具可用性。
- 不把四问中所有可能的补充都强加进去；不要因增加测试、检查或资料而偷偷改变最终交付范围。提示词可以要求执行必要步骤，但本次调用只生成提示词。
- 若用户只给出一个宽泛目标，尽量基于已知信息给出有条件的改写；只有缺少任务对象或关键约束导致无法有意义地改写时才提问。
- 完成四问和改写后停止，等待用户确认或提出修改。不要开始执行新提示词，也不要修改代码、文件或外部系统；用户后续确认执行后，再按确认的要求处理。

## 输出模板

使用用户的语言，通常保持精炼；下列标签可按语境调整：

1. **专业补足**：……（与原目标的关系）
2. **原始材料**：……（可用性或缺口）
3. **方法与工具**：……（具体用途）
4. **独立验证**：……（证据、通过标准与局限）

**改写后的提示词**：

> [原目标和交付物；现有约束；必要的一手材料、方法及验收标准；不扩大的范围。缺失信息用条件或待确认项表达。]

最后简短说明：等待用户确认后再执行。

## 开发场景示例

**输入**：“把已有登录按钮的防重复提交做深一点，改写任务。”

1. **专业补足**：检查请求进行中、失败和完成时按钮状态，以及快速连续点击和页面销毁时的行为，确保原有防重复目标可靠。
2. **原始材料**：查看实际按钮事件处理、请求生命周期、现有测试及相关错误日志；若日志不可用，标明这一缺口，不假定线上已有故障。
3. **方法与工具**：追踪事件到网络请求的调用链，用项目现有测试框架模拟快速连点、请求失败与生命周期变化；以实际架构决定是否需要并发控制。
4. **独立验证**：自动化测试或可复现的请求记录应显示：请求进行中连续点击只产生一次提交；失败后可按既定交互重试；页面销毁不产生错误的后续更新。具体验收以现有产品行为为准。

**改写后的提示词**：

> 在现有登录按钮的范围内，完善防重复提交。先检查实际事件处理、请求生命周期和现有测试，确认当前预期的失败与重试行为；如有可用日志，再核对实际问题。针对快速连点、请求失败及页面销毁等与该目标直接相关的情况，采用适合项目架构的最小改动，并用项目现有测试框架或可复现的请求记录验证：进行中连续点击只产生一次提交，失败后的重试和生命周期行为符合既定预期。保留现有接口与用户流程，不新增登录功能或重构无关模块；预期行为不明确时先说明并确认。

等待用户确认后再执行。
