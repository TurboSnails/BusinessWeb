## 0. 结论先行

1. **现状离"全自动"差的不是算法，是数据层。** 引擎六维中只有3维自动（技术、M1−M2、美债/VIX）。估值、资金、宽度三维要人工录入且存在浏览器 localStorage（`engine.ts:141-143`），而 `summarize` 要求有效维度≥4（`engine.ts:132`），所以**不补录时状态恒为"等待证据"或"趋势防守"**，面板实际上是半手工工具。
2. **真实探测（19次GET，18成功1失败）证明沪深300可以做到"可维护代理版"的大部分自动化**：中证官方PE+成交额（E01/E02）、国债收益率（E05，东财转载）、融资买入额（E07/E08，东财；沪市官方E17交叉）、HK流动性（E12，HKMA官方API）、FRED汇率/美元流动性（E14/E15）。**恒指/恒生科技的估值和成分股宽度没有免费可验证来源（E19失败：仅前端壳页）**，只能显式缺失或从今天起自行累积。
3. **没有任何一维能称"精确版100%无人值守"。** 最干净的是技术维度（价格），其余要么是第三方转载（东财/腾讯），要么口径有缺口（见 §3、§4）。
4. **引擎有3个高严重度问题**：①"趋势防守"优先级覆盖下跌中的底部观察，赔率/底部标签与风险动作耦合在同一个状态里（F1，已按复核修订措辞）；②无状态、无滞回、无冷静期（F2）；③取数脚本一个指数失败就会让整个周更工作流不提交（F3）。详见 §5。
5. **推荐路径**：先修可靠性与留档（P0），再逐个接数据适配器（P1），最后做回放验证和并行影子运行新状态机（P2）。自动数据只产出研究信号与复盘，**不产生仓位指令，不下单**。

## 4. 自动化分层与"精确版 vs 可维护代理版"

**可无人值守（采集、计算、留档、告警）**：价格技术（三市场）；沪深300 PE/ERP/成交；融资买入额及占比（带分母说明）；港股成交/南向/HKMA流动性；FRED 全部；M1−M2 短窗；沪深300 现成分宽度（需先验证云端可达与限流）。
**只能代理**：国债收益率（转载）；宽度（静态现成分）；ETF 份额（仅沪市个别）；离岸人民币；恒科成交额。
**需付费或受限（未核实价格，仅为判断）**：恒生官方估值/历史成分（恒生数据服务）、中证历史成分 PIT、Wind/iFinD/Choice 的全市场宽度、深交所/港交所历史明细。**本轮不建议订阅**。
**必须人工**：恒指/恒科估值首次回填、策略资金与风险预算、最终仓位决策。

| 维度 | 精确版（理想） | 可维护代理版（本方案） | 差距与风险 |
|---|---|---|---|
| 估值 | 中证指数官方PE + 中债官方曲线，按发布日期PIT | 中证PE + 东财国债转载；`firstSeen` 时间戳自累积 | 转载可能改字段；历史回填的"发布时间"是推断 |
| 资金 | 沪深交易所官方两融买入额 ÷ 同范围成交额 | 东财汇总 + 沪市官方交叉；分母指数成交额代理 | 范围不匹配导致比率偏差；非官方接口 |
| 宽度 | 历史成分PIT + 复权日线 | 每周归档"当时现成分"，历史不回填 | 前几年无宽度历史，不能参与回放 |
| 宏观 | 央行发布时间+版本 | 月度快照 + `firstSeen` | 新口径仅20月 |
| 技术 | 官方指数日线 | 腾讯 + 中证/东财对账 | 价格指数不含分红 |
| 海外 | FRED/HKMA/美联储官方 | 同左 + Yahoo 离岸汇率 | Yahoo 非官方 |

| **发布日期/修订** | 引擎用"月份期末"当可得日（`engine.ts:109-110`），真实发布一般晚于期末；回放必须用 `firstSeen`/官方发布表。M1、PE 回溯修订不一定留版本。 |
| **PIT/幸存者** | 宽度用现成分、PE 用现在的指数定义都会前视。必须区分 `backfilled` 与 `observed` 两类事实，回测只用后者做"PIT声明"。 |
| **跨市场收盘时点** | A股 07:00 UTC、港股 08:00 UTC 收盘，美股 20–21 UTC 收盘；原则是 `available_at ≤ decision_at`：周五美股收盘（约20–21 UTC）早于周六 06:00 UTC，周五美股收盘价在技术上可用；**FRED 等源有发布滞后（本机快照中 DGS10 最新比抓取日早约5天，DEXCHUS 滞后约8天），须逐源登记 `available_at` 规则**，不能一概排除周五，也不能默认可用。（撤回此前"周五美股只能用周四"的一刀切表述。） |
| **指数重构/成分历史** | 例行成分调整**不等于**每次重开估值窗口，否则5年窗口永远凑不齐。应分三类处理：①**官方指数自身当期公布的PE**（中证 E01/E02、恒生月度xlsx）按序列连续使用，视为"发布时点口径"，不因例行调样清零；②**用当前成分重算的历史PE**属 `backfilled` 重算，不得与①混用，也不得声称PIT；③**重大方法变更**（指数编制规则/市盈率口径变化）才在事实里记录 `definition_version` 与断点，分位在断点前后分别评估或标注。各次具体调整/方法变更日期我未核实，需后续任务补查。宽度只能基于归档的当期成分，这一点不变。 |
| **月度数据新鲜度** | 官方月PE按月更新，不能套用手工项14天TTL；建议按序列设独立上限（例如月度序列以"次月发布窗口+宽限"为界，数值待预注册），过期则维度 missing。 |
| **指数定义** | 沪深300 PE 若为总股本口径；HSI/HSTECH 估值不可互用（需求文档已强调，应在 schema 中以 `index_id` 强约束）。价格指数≠全收益。 |
| **数据源相关性** | 腾讯、东财、新浪等都是同类聚合，**多源≠独立**。官方源（中证、上交所、HKMA、FRED）才算独立对账锚。 |
| **永久熊/尖顶** | 见 F1/F2：现规则下长熊永远"趋势防守"，尖顶要等两周破位才报。需在回放中测 peak→触发的回撤。 |
| **融资门槛** | 融资制度（保证金比例、标的扩容含ETF、2015去杠杆）使绝对阈值非平稳；应以滚动分位+绝对值双判，并标注制度断点。 |
| **成交额口径** | "前牛峰值20–25%"与代码"52周均量≤0.5"（`engine.ts:82`）不是同一件事，需在规则版本中明确。 |

## 7. 更合理的备选状态方案（须经验证，不是结论）

**问题**：现方案按指标票数共振，既重复计权，又让趋势和极端水平互相覆盖（F1/F2/F12）。

**备选：分层门控 + 滞回状态机（暂名 `cycle-layered-v2`）**

1. **分组而非逐票**：把维度归并为4组，组内先合成再投票——
   - 趋势组：周/月技术、（宽度新高）；
   - 赔率组：ERP/PE 分位；
   - 拥挤/参与组：成交分位、融资占比分位、宽度、南向；
   - 背景组：宏观、海外、流动性（**只能延迟或降级，不能单独触发加风险**）。
2. **趋势决定状态，赔率决定"值得研究的区域"，拥挤度只做否决**：
   状态集：`防守观察 → 底部候选 → 右侧修复 → 趋势持有 → 顶部风险 → 防守观察`。
   `底部候选`不再要求站上20周线，而是"赔率组偏便宜 + 拥挤度低 + 价格处于下降趋势尾段（RSI/回撤极端，不要求反弹）"；
   `右侧修复`需要趋势组转好并**连续确认N周**；
   `顶部风险`由"拥挤度极端 或 趋势破位"**两条独立路径**进入，不必两者同时。
3. **滞回**：进入阈值与退出阈值分离；每次转换后设最短停留期与冷静期；允许"假突破后回退"的路径。N、冷静期长度、各阈值**都是待预注册的参数，不在此给定数值**。
4. **缺失处理**：某组数据缺失→该组为 `missing`，状态机降级为"仅趋势+可得组"，页面显示有效组数；不再用"≥4维"这种计数门槛。
5. **与 v1 并行影子运行**，各自写周度状态，对比差异；不替换已发布 v1 直到验证。

**验证（预注册后执行）**：固定参数文件与规则版本→PIT回放→对比基线（买入持有、定投、简单20周线趋势）→指标：最大回撤、换手、确认延迟、误报/漏报、错过上涨成本、含费用与分红的ETF可执行性→测试窗口至少包括 2015 年A股尖顶、2018 长熊、2021–2024 港股长熊、2022 年低点后的修复、2024-09 急涨；邻近参数敏感性；恒科单列并披露样本短。若无稳定增益，结论写"不支持"并降级为纯观察。

## 10. 自动数据不等于自动仓位决策

- 自动化范围仅到**研究信号、状态记录、质量告警与复盘清单**。系统不下单，不对接券商，不生成"应买入X%"的指令。
- 原方案的 40%–50% / 80%–100% 档位与港股60%–70%、A股70%–80%权重**没有任何验证**，本文与面板都不应把它们包装成建议；在回放通过前保持"策略资金内的候选档位"措辞，或干脆不展示。
- 仓位决策保留给使用者的资金范围与回撤预算（页面已有人工预算设置），自动系统只报告"证据是否支持复核"。
- 阶段成功＝报告交付与可实施设计，**不代表策略已验证**。
