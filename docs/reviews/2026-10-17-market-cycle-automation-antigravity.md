### 2.1 指标相关性与重复投票剖析（Correlation & Double Voting）
- **代码事实**：
  `engine.ts:128` 采用简单计数机制：
  ```ts
  const bottom = count('bottom'), positive = count('positive'), risk = count('risk'), valid = active.length
  ```
  在第 135 行：
  ```ts
  else if (bottom >= 3 && risk === 0) { state = '底部候选'; ... }
  ```
- **量化机制剖析**：
  在统计学与金融计量上，六维并非正交变量。
  1. **估值（Valuation）**（第 78 行计算沪深 300 倒数市盈率减国债利率）由价格驱动（$PE = P / E$）。
  2. **市场宽度（Breadth）**（第 86 行站上 MA200 比例）是个股价格对其历史均价的位置。
  3. **技术指标（Technical）**（第 100 行月 RSI(14)）是指数自身价格动量的超卖度量。
  当市场经历持续下挫时，价格暴跌会同步推动 $ERP$ 达到高位、宽度跌入低位、月 RSI 跌入超卖区。将高度共线性的指标作为独立选票简单加总，容易产生伪共振现象，在单边下行市中过早发出底部聚集信号。

### 2.2 绝对阈值欠验证与制度断裂（Under-validated Thresholds）
- **代码事实**：
  `engine.ts:82-84`：
  ```ts
  signal = market === 'csi300' ? v.financing >= 10 ? 'risk' : v.volumeRatio <= 0.5 && v.financing < 6 ? 'bottom' : ...
    : v.volumeRatio >= 1.5 ? v.south > 0 ? 'positive' : v.south < 0 ? 'risk' : 'neutral' : ...
  ```
- **量化机制剖析**：
  1. **融资买入占比（Financing Ratio）**：代码将 `< 6%` 设为底部、`>= 10%` 设为风险。中国两融业务经历了制度调整（如 2015 年将融资保证金最低比例由 50% 提高至 100%，2023 年 8 月又调降至 80%）。固定绝对阈值（6% 和 10%）在跨越不同监管周期的样本中存在适应性风险，应结合长期滚动分位数评估。
  2. **南向资金净买入（Southbound Flow）**：港股资金维度以 `v.south > 0` 判定为修复、`< 0` 判定为风险。但历史交易中南向资金常呈现持续战略性配置流入，正负符号的周期敏感性较低，属于待实证检验的设计。
  3. **恒生科技成分宽度失真**：恒生科技指数仅由 30 家成分股构成。在 30 家样本下，`breadth <= 10%` 意味着必须 $\le 3$ 家。任意 1-2 家大市值股票异动会导致宽度产生阶跃，直接沿用 5000+ 只全市场宽基的连续百分比阈值并不匹配。

### 2.3 月线确认延迟与保守日历约定（Monthly Confirmation Lag）
- **代码事实**：
  `engine.ts:26-34`（`completedBars` 函数）：
  ```ts
  const end = period === 'week' ? weekEnd(b.date) : monthEnd(b.date)
  if (end <= asOf && b.date <= asOf && (period !== 'month' || b.date.slice(0, 7) < asOf.slice(0, 7))) byPeriod.set(end, { ...b })
  ```
- **机制与影响核验**：
  - **日历保守约定**：代码明确要求 `b.date.slice(0, 7) < asOf.slice(0, 7)`。即使处于 10 月 30 日（当月已近收盘），引擎依然排除 10 月数据，必须等待至 11 月 1 日才将 10 月视为已完成月。
  - **确认延迟属性**：这并非工程错误（Bug），而是为保证月 K 线完全定格而采取的保守设计。其带来的客观权衡是：**根据行情拐点发生的时间，会产生约 0 到 1 个月的结构性确认延迟**。若拐点发生在月初，需要近 1 个月才能得到月线确认；若拐点发生在月末收盘时，延迟仅 1-2 天。在策略设计中，需明确这一延迟对右侧追入与防守出场的具体影响。

### 2.4 尖顶撤退的均线脱幅盲区（Flash Peak Exit Blindspot）
- **代码事实**：
  `engine.ts:99`：
  ```ts
  const broken = w.close < w.mid && prev.close < prev.mid
  ```
  `engine.ts:86`：
  ```ts
  signal = v.breadth <= 10 ? 'bottom' : v.priorBreadth >= 85 && v.breadth < 60 && indexNewHigh ? 'risk' : ...
  ```
- **量化机制剖析**：
  1. **均线滞后脱幅**：在脉冲式暴涨行情中，价格脱离 20 周均线（MA20）幅度较大。当见顶急速回调发生时，初期价格虽然下挫显著，但由于此前基数高，收盘价仍可能高于 20 周均线。在此阶段，数学上 `broken` 条件不会成立。
  2. **新高依赖阻断**：宽度维度的 `risk` 条件包含 `indexNewHigh`（指数当周创 52 周新高）。见顶回落后指数已脱离最高点，无法满足该前提，导致宽度风险票失效。
  3. **防守迟滞风险**：在此场景下，系统难以迅速形成多维风险共振，往往需要等待价格持续回落击穿 20 周线后方能触发趋势防守。因此在尖顶场景中，必须探索更为敏捷的波动率或动量反转辅助触发器。

### 2.5 市场权重等权化的逻辑失配（Market Asymmetry）
- **代码事实**：
  `engine.ts:125-139` 对沪深 300、恒生指数、恒生科技无差别采用 6 维等权。
- **量化机制剖析**：
  港股属于典型的离岸金融市场，联系汇率制使得贴现率与资本流动深度锚定美联储利率政策。现行系统对所有市场均分配 1/6 的海外维度权重，在面对全球美元流动性紧缩周期时，对恒生科技的风险传导权重视角相对有限；反之，若主观设定 60%-70% 权重亦缺乏严密统计验证，反映出跨市场结构需要更合理的分层组织方式。

### 2.6 底部观察与防守动作的解耦修正（与 Claude F1 对齐）
- **代码事实与审查核实**：
  在 `engine.ts:99-100` 中：
  ```ts
  const broken = w.close < w.mid && prev.close < prev.mid
  const signal: Signal = broken ? 'risk' : m.rsi < 35 ? 'bottom' : ...
  ```
  在 `engine.ts:131` 中：
  ```ts
  if (technical === 'risk') { state = '趋势防守'; note = '先复核策略风险预算与减仓条件；无需等待估值和杠杆同时极端。' }
  ```
- **正本清源**：
  此前的报告简略表述为“技术超卖直接凑三票抄底”，该表述不准确，**忽略了代码中 `broken` 拥有最高三元优先级的事实**。
  正如 Claude 审查项 F1 所精准指出：
  - 当市场处于两周破位的持续下跌时，`technical` 维度直接输出 `risk`，而不会输出 `bottom`。
  - 在 `summarize` 中，`technical === 'risk'` 会无条件返回“趋势防守”，**完全覆盖了底部的形成**。
  - **核心缺陷在于体系将“观察性赔率标签”与“操作性防守动作”强制耦合在单一状态输出中**：在长熊单边下跌期，即使估值极度便宜、RSI 极度超卖，底部观察信号被“趋势防守”全盘压制；一旦价格反弹站回均线，估值往往已脱离最佳低位。
  - **正确修正方向**：必须将“赔率/环境状态”（观察层面）与“执行/风控动作”（操作层面）解耦为独立字段，既不能让长熊过早抄底，也不能让防守动作掩盖了战略赔率区间的客观呈现。

### 2.7 Point-In-Time (PIT) 历史回放时点缺失与 14 天人工死锁
- **实测证据（详见 probe-03 与 probe-04）**：
  1. **宏观时点核验**：
     `server/macro.mjs:279` 将 M1-M2 数据打标为报告期月首日（如 `2026-09-01`）。
     `engine.ts:109` 过滤条件为 `monthEnd(d) < asOf`。
     **事实澄清**：当前生产代码为前台观察面板，并未接入自动交易，因此**线上并没有发生“未来交易”**。真正的风险存在于**未来的历史策略回测**：中国人民银行每月货币供应量通常在次月 10-15 日披露，具体日期各月不同。若直接以月首或月末为准进行历史回放，在发布日前会产生数日至十余天的潜在前瞻偏差。离线回放系统必须补齐每期真实的官方公布日期（`available_at`）。
  2. **人工 14 天过期死锁**：
     `engine.ts:74` 与 `132` 规定 3 个人工项超过 14 天未维护即变为 `missing`，导致有效维度恒小于 4，状态机永久锁定在“等待证据”，证实了现有面板对人工周期性维护存在硬性依赖。

## 三、恒生科技（HSTECH）发布时点、历史限制与方法变更核验

### 3.1 真实发布时点与实盘数据核验（实测证据：probe-01）
- **发布事实**：恒生指数公司于 **2020 年 7 月 27 日** 正式推出恒生科技指数，基日为 2014 年 12 月 31 日，基点 3,000 点。
- **实盘行情跨度**：
  根据腾讯行情源实测：HSTECH 首根月线日期为 `2020-07-31`，截至 2026-10-16 共有 **76 根月线**。
- **60 个月门槛的历史限制**：
  `engine.ts:98` 与 `market-cycle-snapshot.mjs:31` 要求月线 $\ge 60$ 根。**在 2025 年 7 月之前，HSTECH 的真实交易月线不足 60 根**。在此之前若严格运行该代码，该指数的技术维度将因数据长度不足而无法产出。

### 3.2 2014–2020 回填数据的幸存者偏差与方法变更
- **模拟回填性质**：
  恒指公司发布的 2014–2020 点位属于**事后回溯模拟计算（Backfilled Simulation）**。
- **实证约束与严谨性要求**：
  1. **幸存者偏差（Survivorship Bias）**：2020 年入选的 30 家巨头是经历了前期竞争筛选的成功企业，以其倒推历史包含后见之明，无法反映当时真实投资组合的下行风险。
  2. **监管与市场范式突变**：2020 年底起互联网反垄断、中概监管等外部环境发生了根本性变迁，2020 年前的回填模拟无法检验模型在这些结构性突变中的鲁棒性。
  3. **单周期统计限制**：从 2020 年 7 月至今约 6.2 年，HSTECH 实盘仅经历约一个半宏观波动周期，有效样本较短，严禁使用 2014–2020 回填数据冒充实盘交易并宣称所谓“经过多轮周期严格验证”。

## 四、双轨解耦状态机（Dual-Track Decoupled State Machine）方案

针对“指标伪共振”与“底部观察被防守状态覆盖”的核心缺陷，本方案设计一套**双轨解耦（Dual-Track）决策状态机**，将**战略赔率区间**与**战术执行风控**拆解为相互独立又分层协作的两个维度。

### 4.1 核心理念：双轨并行输出与风控终极门禁
不再强制将所有逻辑挤压进单一状态标签，而是并行输出两个核心字段：
1. **战略赔率状态（Regime / Valuation Tier，观察性）**：
   - `DEEP_VALUE`（高赔率深度低估）：ERP $z \ge 1.5$ 或历史分位处于极度低位；
   - `FAIR_ZONE`（合理定价区间）；
   - `BUBBLE_RISK`（负赔率极度高估）：ERP $z \le -1.0$ 或估值极端泡沫化。
2. **战术行动姿态（Action / Execution Posture，操作性）**：
   - `DEFENSIVE_HOLD`（趋势防守 / 空仓观察）：存在跌破 20 周线或快速破位；
   - `WATCHING`（耐心等待 / 保持现状）；
   - `REPAIR_ENTRY`（右侧动量修复 / 允许试探）：价格突破均线且获得动量确认；
   - `TREND_TRACKING`（顺势持有）：均线多头排列，量价平稳。

> **风控门禁原则**：当“战术行动姿态”为 `DEFENSIVE_HOLD` 时，即使“战略赔率状态”处于 `DEEP_VALUE`，系统在操作层面上依然**严格执行防守减仓或禁止大额加仓**，但在观察卡片上**明确高亮显示当前处于高赔率区间**，使得左侧赔率跟踪与右侧风控纪律得以完美兼顾。

### 4.2 候选转移规则与防抖机制（纯研究假设）
为应对假突破与尖顶风险，提出以下候选机制供后续验证（**明确声明：以下所有阈值均为待测试候选假设，不作为上线推荐**）：

1. **慢速趋势防线（候选示例）**：
   - 连续 2 周收盘价位于 20 周均线下方，且收盘价低于均线幅度达候选阈值（如设 $\ge 1.0\%$ 缓冲以防杂波），触发 `DEFENSIVE_HOLD`。
2. **敏捷波动防线（应对尖顶脱幅的候选探索）**：
   - 当战略估值处于 `BUBBLE_RISK` 或价格严重脱离均线时，若单周振幅剧烈放大（如达到典型真实波幅 ATR 的数倍）或出现放量跌破前低，触发预警性防守复核，弥补纯均线系统的迟钝。
3. **迟滞防抖（Hysteresis）与冷却期（Cooldown）候选**：
   - 突破均线需具备一定比例确认（如候选 $\ge 1.5\%$）；从防守状态转回可操作状态前，设置数周的候选冷静观察期（如 4 周候选），避免在均线附近反复震荡磨损。

## 五、无偏历史验证体系设计（严禁编造胜率）

为建立科学严谨的量化研究基准，必须坚持去偏差化，坚决杜绝通过调参捏造完美绩效。

### 5.1 数据去偏差规范
1. **时点严格对齐（PIT Alignment）**：
   - 建立 `event_date`（经济报告期）与 `available_date`（实际公开可获取时间）双时间戳；离线回放时严格要求任何特征计算仅可使用 `available_date <= decision_at` 的历史快照。
2. **动态成分与幸存者偏差隔离**：
   - 计算成分股汇总特征时，明确区分 `observed`（当时公布口径）与 `backfilled`（后验重算）。对于市场宽度，必须使用当时生效的历史成分名单归档，不可使用当前静态名单向历史渗透。

### 5.2 验证分期与向前滚动检验（Walk-Forward Validation）
严禁在全样本上全局调参，建议划分为独立检验窗口：
- **阶段一（校准期）**：用于确定基础状态机结构与特征组合；
- **阶段二（样本外盲测）**：冻结全部规则与参数，测试未参与拟合的历史区间；
- **阶段三（滚动向前走前实测）**：检验最新市场常态与适应性。

### 5.3 参数敏感性曲面与悬崖探测
- 对均线窗口、极值分位阈值等核心参数进行邻域扰动（如 $\pm 10\%, \pm 20\%$）；
- 检验绩效指标在参数空间中是否呈现平缓分布（Plateau）；若存在单一参数优异但微调即崩塌的现象，判定为过拟合尖峰并坚决摒弃。

### 5.4 交易摩擦与双基准（Benchmark）对比
回测评价必须扣除现实交易摩擦（佣金、印花税、冲击滑点、ETF 跟踪误差），并同时设立两个基准进行严密检验：
- **基准一：买入持有（Buy-and-Hold）**：检验主动择时是否超越被动投资；
- **基准二：简单单均线趋势规则（Simple Trend）**：检验多维复杂状态机是否相比基础均线带来了真实的增量信息增益，避免徒增模型复杂度。

## 八、与协作执行者（Claude / Kimi）的真实分歧核验与消除方案

### 8.1 与 Claude 的架构设计分歧：彻底双字段并列 vs. 具备最高否决权的主姿态展示
- **分歧描述**：
  - **Claude 方案**：主张将“赔率/底部观察”与“风险动作”彻底拆分为两个独立的展示字段，完全不设置单一的综合状态标签，避免任何形式的覆盖。

- **理论依据与分歧实质**：
  在实际投资心理学中，若仅展示两个并列字段（例如同时显示“极度低估”与“建议防守”），缺乏明确主从关系时，普通投资者容易根据自身屁股（套牢心理）选择性关注“极度低估”而忽视“建议防守”，造成认知混乱。Antigravity 认为应确立**“风控拥有最高否决权”的主从层级**。
- **消除分歧的下一验证步骤**：
  在 P1 阶段设计两种 UI 呈现原型（彻底并列 vs. 主从层级），在 2018 年底（估值极低但均线破位）与 2021 年初（均线强势但估值泡沫）两个经典历史切片下进行交互推演，评估哪种结构更能有效防止非理性的逆势操作。

### 8.2 与 Kimi 的数据成熟度分歧：东财国债字段直接 P0 上线 vs. 需先期官方字典校准
- **分歧描述**：

- **消除分歧的下一验证步骤**：
