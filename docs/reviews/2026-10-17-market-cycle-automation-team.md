# 牛熊周期自动化：四执行器讨论与manager实施裁决

日期：2026-10-17。基线：已发布提交 `5538172`。本轮为用户指定的 dev-team 方案审查与小规模数据可行性核验，**没有改动生产代码、上线新策略或完成策略回测**。

## 结论

采用“自动采集、质量检查、确定性计算、留档和复盘；风险预算与交易执行由本人决定”的路线。主要障碍是数据口径、长期历史、历史可得时点和运行可靠性，而非缺少更多技术指标。

原方案保留六维证据展示；下一版把**赔率区域、趋势状态、风险约束、数据质量**分别输出。估值便宜与趋势防守可以同时成立，不能让单个标签抹去另一个事实，也不能为了显示“底部”取消防守。宏观与海外主要提供背景/约束，不再默认等同于独立买入票。

“尽量全自动”可作为工程目标，但当前不能承诺原始六维指标全部免费、全历史、无人维护。数据不足应自动报缺失并继续发布其他有效结果，而不是由人工每两周重填三个维度，也不是用代理偷偷补齐。

## 哪些可以自动化，哪些尚有缺口

下表“有来源”只表示已取得接口/文件与字段证据，**不代表生产实现、长期稳定或策略有效**。Claude/Kimi为本机只读探测；官方港股PE由manager独立下载解析。共享证据不重复计为独立验证。

| 维度 | 下一版自动化路径 | 上线前缺口 |
| --- | --- | --- |
| A股估值 | 中证沪深300估值时间序列 + 中国10年国债；按同日交集计算简化ERP、预注册滚动分位/z-score | `peg`字段PE语义及国债期限映射需官方口径核对；国债接口实际每页最多500条，首次需分页，不能拿500条冒充5年历史 |
| 港股估值 | 恒指、恒生科技各自官方月PE文件，定时下载、校验与归档 | 当前这两份文件各仅12个月，不能计算5年分位；继续寻找可核长历史，未找到前显示观测PE与“长期分位缺失”，不插值伪造 |
| 资金与杠杆 | 两市融资买入额、同覆盖成交额、南向背景、宽基ETF份额白名单 | 分子/分母须同市场、同证券范围、同日；单指数成交额不能直接充当全市场分母；沪市ETF份额可取不等于深港已齐全 |
| 市场宽度 | 官方当期成分 + 逐股至少200个合格日收盘 + 增量缓存，自动计算MA200宽度 | 先做三个指数各自成分池；全A股是另一范围，不改名冒充。停牌/新股/退市、复权、覆盖率与历史成分PIT必须单独处理 |
| 国内宏观 | 复用M1/M2自动链路，记录口径、观测月、真实发布时间、修订与首次发现时间 | 2025年新口径不与旧口径直接拼接。历史发布日缺失时不得宣称PIT回测；“次月15日”只能是明确标注的敏感性假设，不能冒充实际披露日 |
| 海外环境 | FRED美债/VIX、明确标识的CNH、HKMA港元流动性；同币种相对收益对照 | CNH与在岸CNY不能静默互换，失效时缺失或切换独立指标。周六决策可使用届时已发布的周五数据，按 `available_at <= decision_at` 筛选 |

## 讨论中的分歧与裁决

| 议题 | 不同意见 | manager裁决与验证条件 |
| --- | --- | --- |
| 融资占比分母 | Claude倾向维护简单的指数成交额代理；Kimi倾向交易所每日概况合并 | **先核覆盖，再比数值。** 上证综指、深证综指的总额与ETF/两融标的覆盖均须明确；深证成指399001不是深证综指399106。数值接近不证明口径相同，不能只凭“偏差<5%”就认证 |
| 底部与防守 | Claude建议赔率标签与动作分开；AGY更强调宏观/风控主从层级 | 双轨输出：`valuation_zone` 与 `trend_state` 并列，`risk_gate`约束动作，`data_quality`约束可作何种推断；不让估值便宜直接突破风险预算，也不隐藏下跌中的低估观察 |
| 缺数与“全自动” | 可以换代理维持计票，或保留缺失降低结论强度 | 代理使用独立ID、版本和说明；不得偷偷换源/币种/股票池/定义。缺关键证据保留低确定性输出，自动生成质量问题，不凑满六票 |
| Node或Python | OpenCode倾向零依赖Node；数据模块也可借助Python解析生态 | 先复用Node/TS与小型适配器；遇到官方xls/xlsx解析或成熟采集库确有优势再隔离Python。未安装某个库不是否定某种语言的依据 |
| 历史宽度 | 从当前成分回填容易；严格历史成分难补 | 两类结果分别命名并列偏差；先归档从现在开始的当期名单。尚未建立PIT历史，不等于证明免费历史一概不可得 |
| 高并发与免费成本 | OpenCode给出固定并发、秒数及费用保证 | 不采纳。先少量云端探测、低并发、总量上限、退避和熔断；真实运行后记录耗时/字节/配额。费用按账户与当期规则核，不承诺零成本 |

## 建议的最小升级架构

`分源采集 → 原始版本/增量缓存 → 标准事实 → 质量门禁 → 确定性特征 → 分层状态 → 自动复盘留档 → 前端`

每条事实至少带 `metric_id`、`market/index_id`、`universe_id`、`unit/currency`、`adjustment`、`observation_date`、`available_at`（未知可空）、`first_seen_at`、`fetched_at`、`source/version`、`kind=observed|backfilled|proxy`、`coverage` 和 `quality`。真实发布日未知时不得把抓取时间回填为历史发布日期。

- 原始缓存不与每周公开页面全量重复打包；公开紧凑快照、状态、质量与输入哈希。使用有保留策略的缓存/归档，避免Git仓库随每周全量日线膨胀。
- 日频、周频、月频各有新鲜度与发布宽限；14天不是通用TTL。旧值保留原日期，失败不能改成“刚更新”。
- 单源/单市场失败隔离：有效产物先按验证和原子写入规则提交，质量与失败状态另报；不能因一个指数非零退出就使所有成功数据也丢失。
- 从server/CI计算规则并保存周度状态快照，前端负责显示。LLM不参与日常打分或改阈值，避免每周不可复现判断。
- 自动生成周报/质量事件文件；外部通知通道、凭证与收件人另行配置，本轮未发送通知或创建外部告警。

## 可直接接手的实施顺序

| 阶段 | 文件范围（候选） | 行为验收 |
| --- | --- | --- |
| P0：质量契约与容错 | `src/features/market-cycle/`事实schema；`scripts/market-cycle-*.mjs`；现有宏观workflow或独立cycle workflow | 失败保留旧日期；单源失败不阻断其他有效产物；非法/未来数据不计入；每市场明确exact/proxy/missing；自动状态留档不依赖打开浏览器 |
| P1：估值、资金、海外自动接入 | 独立ERP、融资、港股PE、汇率适配器与紧凑快照；前端自动证据优先、手工仅作有记录覆盖 | 国债分页完整、期限和PE语义有可复核映射；融资分子/分母同覆盖；月PE可更新但不足历史不出长期分位；CNH失败不静默换CNY |
| P2：MA200与份额 | 当期名单适配器、逐股增量缓存、coverage报告、ETF白名单与事件记录 | 每证券≥200个合格日线；不混MA250；同范围分子/分母；证券排除可追溯；成分归档；不把CSI300宽度称全A；缺数不能伪造改善 |
| P3：规则影子运行与验证 | 版本化参数、状态转换、回放与报告工具、前端双轨卡片 | 新旧版本并行；进入/退出门槛及冷静期预注册；用真实可得时点；成本/分红/交易可行性；与买入持有、定投、简单20周趋势比较；不强求跑赢或编造命中率 |

第一次接入前做少量云端可达性演练；之后至少观察若干连续周的自动更新、失效降级与归档。这只能验证运维，不代表策略收益通过。没有历史数据或足够周期时如实降级为观察工具。
