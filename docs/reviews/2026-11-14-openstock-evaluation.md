# OpenStock 引入评估 · 团队裁决（2026-11-14）

问题：开源项目 [OpenStock](https://github.com/Open-Dev-Society/OpenStock)（AGPL-3.0，Next.js + MongoDB + Finnhub + TradingView）哪些功能值得引入、放在哪里、如何优化。

过程：dev_team（Orca Run `run_76b491e51317`）。Codex 写架构/数据评估、Claude 写产品/前端评估（并行）→ Cursor 交叉审查并独立核实关键事实 → manager 裁决。Kimi 原定审查，Orca 两次派工均未把任务送进 Kimi Code 2.5.2 输入框，改派 Cursor。原始报告：`.dev-team/runs/openstock-eval/reports/{arch,design,review}.md`（本地，未入库）。

## 结论

**不整体集成**：定位不同（行情终端 vs 研究笔记）、不覆盖 A 股、港股无 K 线、技术栈不同、AGPL 会传染整站。只借鉴思路，用官方第三方组件或自己实现，不复制其代码。

站内已有 OpenStock 的大部分体验骨架（⌘K 面板、候选池站内提醒、`/pulse` 自绘热力图、`/watch` 指数脉搏）。真正的缺口两个：**公司详情页没有价格走势**，**候选池提醒只能在站内看到**。

## 已知风险

- 部署顺序：前端先于 API 上线时，带 `alert` 的云同步写入会被旧 API 拒绝（数据留本地、标记未同步）。Vercel 同时部署前后端，影响很小。
- 部署时仍开着的旧版页面标签读到新格式本地数据会当作无效；刷新页面即可。
- 美股交易所映射来自 yfinance 原始数据，581 个代码有 1 个（CBOE）未解析，用裸代码交给 TradingView 自动识别。
- 站点目前没有深色主题，TradingView 组件固定浅色。
- 未在真机、200% 缩放、读屏软件上验收。
