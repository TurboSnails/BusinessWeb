# 估值列表展示：Claude 独立审阅（2026-10-22）

范围：只读。已读 SKILL.md、`CompanyValuation.tsx`、`model.ts`、`company-valuation.css`、`ResearchNotes.tsx` 的 `renderProgress`（筛选与「估值」列）、三份现有测试、`testFixture.ts`，并对 `public/data/company-valuations/*.json` 全部 1540 条做了统计（968 有数值、572 insufficient；967 undated、1 future、0 present；全部 `review.mode=programmatic`、全部 `conditional`）。未改代码、未改 Skill、未重做研究。下文数字都来自这次统计。

## 一句话结论

当前设计的"醒目判断 + 小字限定"方向对，但有三个事实需要先处理：

1. 三个"基准日估值区间"筛选在现有数据上**必然返回 0 条**（见 §3）。
2. 列表里的颜色和百分数在 968 条上几乎同一档证据强度，却被画成同样醒目。最大的百分数大多是输入问题，不是机会（见 §2）。
3. "情景参考"和第三行"PE · 未定期限 · 报价日"在 99.9% 的行上是常量，占了空间却不提供区分信息。

## 1. 醒目判断 vs 证据可信度；单点与三价区间

### 现状的问题（带反例）

- **判断符号与区间位置不一致。** 968 条中，现价在 low–high 区间内 562、低于 low 264、高于 high 142。但绿色（价格低于基准）有 679 条、红色 289 条。有 **265 条**"低估或高估超过 15%，但现价仍在自家区间内"，例如台积电 ADR（现价 420.22，区间 374.16–654.79，基准 514.48 → 列表"低估 18.3%"，而区间位置是"内部"）、Vertiv（现价 206.08，区间 148.92–422.87，基准 367.71 → "低估 44%"）。读者看到绿色大字，看不到"自家情景区间其实包含现价"。
- **基准点本身常被低档拉偏。** Vertiv 的倍数是 16.2× / 40× / 46×，且 `forwardYearBound=false`（预测年度未绑定）；基准价是低档价的 2.5 倍。单点"基准"在这种记录上承载的信息比看起来少。
- **百分数分母。** 列表用 `现价/基准−1`（折价率），详情页用 `估值/现价−1`（空间）。同一家公司，列表"低估 20.0%"，详情页 `+25%`（测试夹具 80 元的情形）。Skill 允许两者并存但"必须分开命名"。当前列表只写"低估"，没写分母。另外折价率在低估侧封顶 −100%，在高估侧无上限：中国铁建"低估 74%"其实是基准价为现价 3.9 倍，而三六零"高估 2519%"这类数字没有阅读意义。

### 建议：单点 + 区间合一，不恢复长表

在列表单元格里加一条**极小的区间条**（约 110–130px，纯 CSS/SVG）：`低 ──┼── 高`，基准处一条竖线，现价一个点。点落在条内/外、偏哪一侧，一眼可见；不增加文字行。

```
▼ 较基准 −18%   ├──●──┼────┤
基准 514 · 现价 420 USD
核对项：币种待核
```

- 数字仍用基准点（便于排序），区间条给"不确定性与位置"，tooltip/详情页再给 `低–高` 数值与推导。这样既不恢复长表，也不用一个孤立的单点。
- 词汇：undated/future 行**不用"低估/高估"作结论词**，改为描述算术的"较基准 −18% / +25%"。用"低估/高估"只留给 `present`（目前 0 条）。理由：Skill 明确 undated"不认证为今日内在价值"，future"不能直接贴上今日低估标签"；现在是靠 0.7rem 小字"情景参考"来抵消 0.94rem 加粗的"低估"，这是视觉上的强弱失衡。唯一的 future 记录（SOFI，目标 2027-12-31，现价 14.3 / 基准 19.2）现在显示"低估 25.5%"+小字，是最直接的违规样例；应改为"至 2027-12-31 情景 +34%"（用相对现价空间，并带期限，且不进入"今日位置"筛选）。
- 与 Coordinator 的不同意见：**不赞成把分母改成"估值/现价−1"来统一**。折价率更接近"现价偏离基准多少"的直觉，也已写入测试。只需改成明确命名（"较基准 −18%"）并在 tooltip 注明分母；超过 ±100% 时显示倍数（"约为基准 3.9 倍"/"基准的 0.26 倍"）而不是 2519%。

### 证据可信度：用"核对项"代替无差别的 conditional 徽标

全部 968 条都是 programmatic + conditional，所以"条件初稿"徽标没有区分力（当前也已正确地从列表去掉）。能区分的是数据里**已有的类别事实**（不是新阈值）：

| 核对项（类别） | 判定依据（现有字段） | 命中条数 |
|---|---|---|
| 预测年度未绑定 | `inputs.forwardYearBound === false` | 355 |
| 缺情景 EPS | `inputs.researchScenarioEPS.base == null` | 371 |
| 币种待核 | `inputs.financialCurrency !== inputs.quoteCurrency` | 111 |
| 前瞻 EPS ≤ 0 | `epsForward <= 0` | 少量（需实测） |
| 报价日缺失 | `price.date == null` | 2 |

三个反例：
- **中国铁建 (hk:01186)**：财务币种 CNY、报价币种 HKD，基准 17.02 = `1.5477 × 11`，没有看到 CNY→HKD 换算，对应现价 4.35 HKD，隐含 PE 约 2.8×。"低估 74%"主要来自研究倍数未重估，同时有币种口径问题。这类行不该与"所有输入对齐"的行一样绿。
- **三六零 (cn:601360)**：TTM EPS 0.11，前瞻 EPS 0.01，倍数 22/32/44，基准 0.32，现价 8.38 → "高估 2519%"。
- **人民网 (cn:603000)**：TTM EPS 0.22，前瞻 0.13，研究倍数 13×，基准 1.69 对现价 16.77 → "高估 892%"。

按偏离度降序，列表**最顶端恰好是输入最可疑的记录**。核对项应用文字呈现（"核对项：币种待核 · 期限未绑定"），不用分数，不用"高/中/低可信度"。

整体对应 Skill 里"条件初稿≠认证"的要求：核对项是"哪里还不能信"，不是"多可信"。

## 2. 最值得做的 3 项改进（按优先级）

### P1　修复"区间位置"筛选在 undated 数据上全空
- 事实：`matchValuationFilter` 对 `below/within/above` 要求 `kind === 'present'`，现有数据 `present = 0`，三个筛选对任何市场都返回 0 条；`numeric`（有估值或情景数值，968）和 `undated/future`、`waiting` 才有结果。用户点"低于基准日估值区间"只会看到空列表。
- 做法：位置筛选对 `undated` 开放，**标签改为"低于情景区间 / 区间内 / 高于情景区间"**（不再写"基准日"）；`future` 仍排除于"今日位置"，单独走"未来情景"。这不违反 Skill：相对三价区间的位置是对输入数字的描述，不是今日内在价值认证。
- 需改的测试：`model.test.ts` 里 `matchValuationFilter('within', undated)` 当前断言为 false，要按新语义更新，并保留 future 不进位置筛选的断言。

### P2　默认排序：先"无核对项"，再按偏离度；并在列表加区间条
- 事实：`renderProgress` 没有任何估值排序（line 233 的 sort 是林奇列表）。用户要找"最低估"自然会想到降序排；但最大偏离几乎都是输入问题。
- 做法：增加一个排序选项"按较基准偏离"，默认键 = (核对项数量升序, 偏离度)；排序必须在 `slice(0, limit)` 之前；`insufficient` 一律排最后。区间条见 §1。
- 取舍：216 条无任何核对项（flags0），469 条 1 项，251 条 2 项，32 条 3 项（按上表四类统计）。这给"先看干净的"一个实用入口，但没有对"干净"做任何投资含义的声明。

### P3　把常量信息移出行内，保留例外
- 事实：`情景参考`在 967/968 行出现；第三行"PE · 未定期限 · 报价 …"中，PE 占 958/968，未定期限占 967/968，报价日只有两个值（10-19 与 10-20，各市场收盘不同）。
- 做法：在"估值"列头与 `rn-hint` 里一次性说明"本列全部为未定期限情景（PE 为主），不是今日内在价值"；行内只在**偏离常态**时显示：方法≠PE（如 10 条 Dividend）、期限≠未定期限、报价日早于该市场最新日、价格缺失。这样行内文字少一行，核对项那一行才有位置。
- 备注：第二行"基准 X · 现价 Y 币种"保留，因为它是人核对算术的最小证据。

不在前三的：详情页 `pct()` 与列表分母并存的说明已有脚注，改命名后基本够用，不单列。

## 3. 筛选、排序与颜色语义

**筛选（两维，不是 8 个并列按钮）**
- 位置：全部 / 低于情景区间 / 区间内 / 高于情景区间 / 未来情景（单点期限）。
- 数据：全部 / 无核对项 / 有核对项 / 等待证据（insufficient 572 条）。
- 删除 `numeric`（它只是"等待证据"的补集）和 `undated`（几乎等于全部）。与评级、成熟度已有的两排按钮并存时，不再多加一排 8 个 chip；可折叠成两个下拉。

**排序**：偏离度（升/降）、区间宽度、核对项数量；`insufficient` 恒在末尾；同键用代码稳定排序。

**颜色**
- 我**不推荐把绿/红作为"低估/高估"的主语义**。A 股/港股用户习惯"红=涨/好、绿=跌"，本站又覆盖美股，同一列里红色表示"高估"与行情红涨的习惯相反，容易被读成"利好"。而且这是 undated 情景，不该用交易所涨跌色给出强结论。
- 折中方案（二选一）：① 低于基准用冷蓝、高于基准用暖橙，等强度，不用红绿；② 若保留绿/红，则**只在无核对项的行上着色，有核对项的行灰化**，且始终带 ▼▲ 符号与文字（色盲与打印可读）。我倾向 ①+灰化。
- 灰色=缺价/缺项/不可比；"接近基准"用中性色，当前 `deviation === 0` 才触发"接近基准"，四舍五入到 0.1% 才算接近，实际几乎不会命中；建议以显示精度内为 0 判定，不新增容差阈值。

## 4. 明确不推荐的过度设计

1. 综合可信度分数、星级、"证据强度条"——Skill 明令不以综合分数替代证据，且全部是程序化初稿，分数只会制造虚假精确。
2. 统一"买入区/目标回报率/安全边际 X%"门槛，或"低估超过 30% 才高亮"——Skill 禁止无依据统一阈值。上述核对项是类别事实，不是阈值。
3. 前端猜测汇率或自动 FX 折算——币种口径是上游数据问题，应由估值产出方修正，前端只标"币种待核"。
4. 三情景概率加权、期望值、年化——undated 不报年化；概率可留空。
5. 为每行画迷你走势图/价格曲线、实时报价轮询——报价日期是证据的一部分，不称实时。
6. 在列表里恢复方法对比表或 PEG/PB 并列——当前 968 条只有 1 个数值方法，没有第二方法可对比；展示空列只会增加噪声。
7. 把"低估/高估"加粗版重新贴给 undated 或 future，再用小字抵消。
8. AI 逐行自动点评、"值得关注"榜单。

## 6. 可验收标准

1. **筛选可用**：用现网 JSON，选"低于情景区间"返回 264 条、"区间内"561（562 含 SOFI future）、"高于情景区间"142（以实现后实测为准，三者相加 = 968 − future 数）；不再出现 0 条的"位置"筛选。future 记录不出现在任何位置筛选，仅出现在"未来情景"。
2. **不对 undated/future 使用"低估/高估"结论词**；SOFI 显示为带 2027-12-31 期限的相对现价空间，不显示"低估 25.5%"。`present` 仍可使用"低估/高估"（以夹具测试覆盖）。
3. **一致性**：任一行上，数字的正负、区间条中现价点与基准线的相对位置、aria-label 三者方向一致；单测覆盖 −18%（区间内）、−74%（低于区间）、+892%（高于区间）。
4. **极端值**：|偏离|>100% 时显示倍数，不出现四位数百分比；三六零、人民网不再显示"高估 2519% / 892%"。
5. **核对项**：中国铁建显示"币种待核"，Vertiv 显示"期限未绑定"，无核对项的记录该行为空；核对项来自字段而非新阈值，单测断言每类的判定字段。
6. **排序**：默认键 (核对项数, 偏离度)，排序在分页 `slice` 之前；insufficient 恒末尾；切换排序后"显示更多"计数不变。
7. **常量去重**：`情景参考` 与"未定期限"不再在每行重复；方法≠PE、期限≠未定期限、价格缺失、报价日异常时才在行内出现；列头提示存在。
8. **颜色**：在 375px 宽、浅/深色、灰度截图下仍可通过文字与 ▼▲ 判断方向；有核对项的行着色弱于无核对项的行。
9. **测试**：`CompanyValuation.test.tsx` 现有 5 个用例中，"接近基准"与"情景参考紧邻"两个要更新；`model.test.ts` 的 `within(undated)` 断言要更新；其余（缺价、等待数据、币种/倒置拒绝）保持。
10. **边界声明**：页面任何位置不出现"认证""买入区""目标回报率阈值"；`present=0` 时 UI 不假装存在基准日估值。

## 7. 局限

- 核对项的命中条数来自对 JSON 字段的直接统计，币种待核的 111 条仅表示字段不一致，不等于一定算错（ADR 的每股折算可能已在上游处理）；铁建一例是根据 `inputs` 与公式反推的，没有重读财报。
- 未运行页面截图；区间条与配色的视觉建议需要在实现后实际看一遍。
- 前瞻 EPS ≤0 的条数未统计，需实现时实测。

## 8. 对协调者抽查消息的回应（首行用区间位置还是单点方向？）

我的统计与你一致：低于 low 264、区间内 562、高于 high 142，三个位置筛选当前全为 0。我的结论是**首行保留单点方向的数字，但与区间位置合成同一视觉元素，而不是二选一**：

- 首行 = 方向 + 数字（"较基准 −22%"）+ 紧贴的区间条。方向给"一眼看出高低"，区间条的点位给"这个判断是否出了自家情景区间"，两者在同一行同时读到，不新增文字行。
- 着色强度由位置决定：现价在区间外（264 + 142）用完整色；区间内（562）用浅色/描边，避免 MSFT 这类"区间内的 −22%"和"区间外的 −22%"被画成同样强度。这样不必另造一个"区间位置"词汇，也不需要首行写两个结论。
- 不建议只用区间位置作首行：它只有三态，丢失排序信息，且 58% 的行都会落在"区间内"，首行几乎没有区分度。
- 三项最终优先级不变：P1 位置筛选对 undated 开放；P2 默认排序 + 区间条（含着色强度）；P3 常量信息移出行内。
