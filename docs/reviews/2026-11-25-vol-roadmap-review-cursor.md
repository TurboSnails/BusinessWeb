## 1. 总体判断

计划方向对：降波动靠风险预算（上限）+ 预注册多资产检验，比继续加美股择时规则靠谱；「两套引擎一致才上线」与现有审稿实践一致（`docs/research/vol-target-2026-11-25/README.md` 已有独立 Python 复算到小数点后 3–4 位）。

**能达成「降低波动、结论可靠」吗？**——能达成「可靠地知道该不该做多资产」，不一定能达成「多资产一定通过门槛」。工程上最大的成功标准应改写成：数据可核、口径可复现、不通过就停在「调低上限」。这与第 4.4 步一致，应前置为总验收哲学。

**最大三个风险（工程/数据）：**

1. **第 1 步用 `bt`「验收复现」被高估**：现行 E1 口径（次月第 3 交易日成交、股息按交易日分摊、期内每日再平衡、成本只进夏普等）高度定制（见 `docs/research/late-cycle-2026-11-25/run.mjs`），硬套 `bt` 会把差异埋在框架里，拖死后续多资产。
2. **国债/黄金长历史总回报的近似误差与制度断点**：GS5/GS10 月均收益率久期定价 ≠ 真实总回报指数；黄金 1974 年前私人持有受限、来源切换易造成伪稳健。多资产结论会被数据口径绑架。
3. **部署/提交节奏（0.5）已是现网阻塞**：`macro-snapshot.yml` 等一改 `public/data/*` 就 push，Vercel 跟部署；今天额度打满会直接卡住 0.1/0.2/0.3 的页面核对。不先止血，后面研究提交会反复撞墙。

## 3. 重点问题答复（工程视角）

### 3.1 开源工具选型

| 库 | 适合做什么 | 适合本路线图？ | 许可证 / 维护 / 3.14 |
|---|---|---|---|
| **pandas + numpy（直写）** | 复现 E1/VT、日净值、对数 | **首选第二引擎** | 成熟；钉在 **Python 3.12**（与仓库一致），不要用 3.14 跑研究 |
| **`bt`** | 策略树、组合回测 DSL | **不适合当复现验收框架**；最多做多资产「对照实验」 | 计划写 MIT——**需核实**当前 PyPI/仓库 LICENSE；对 3.14 wheels——**需核实** |
| **vectorbt** | 向量化、高频/大规模参数扫描 | **过重**；E1 定制成交日难表达 | 许可证可能含商业条款——**需核实**；3.14——**需核实** |
| **Riskfolio-Lib** | 风险平价、CVaR 等权重 | **适合第 3 步生成 M2/M3 权重**，不跑 E1 | BSD 类——**需核实**；依赖 cvxpy 等，3.14——**需核实**，建议 3.12 |
| **PyPortfolioOpt** | mean-variance / 分层风险平价 | 与 Riskfolio **二选一**即可（优先 Riskfolio 若要风险平价；PPO 更轻） | MIT——**需核实**；3.14——**需核实** |
| **quantstats** | 报告/撕页统计 | **可选**：净值出来后再生成报告 | Apache——**需核实**；不要让它定义夏普口径（必须自写与 JS 同式） |

**结论：**

- 「低频多资产配置 + 第二套引擎复现现行 JS」→ **拆开**：引擎 = pandas；配置权重 = Riskfolio 或 PyPortfolioOpt（第 3 步才引入）。
- **不值得**为第 1 步引入 `bt`/`vectorbt`。框架省不了那 ~150 行日环模拟（`late-cycle/.../run.mjs` `simulate`），反而增加「框架默认再平衡/费用/交易日」暗坑。
- 固定版本：`research-py/pyproject.toml` + `uv.lock`，`requires-python = ">=3.12,<3.13"`（或 `==3.12.*`），CI `setup-python 3.12`。本机 3.14 仅作系统 Python，研究用 `uv python pin 3.12`。

### 3.2 复现验收是否现实？差异热点与定位法

**数字门槛现实吗？**  
**现实**——前提是复现「按日再平衡 E1 基线」，不是「期内买入持有」。出处：

- 夏普 **0.593**、按日最大回撤 **−33.0%**：`docs/research/vol-target-2026-11-25/README.md`、`daily-execution`、`late-cycle` 多处一致。
- `late-cycle` 明确：复现门槛用期内买入持有（夏普 **0.588**）；候选比较用按日再平衡（**0.593**）。计划 1.2 写的 0.593 应对齐后者。
- 差异 **&lt; 0.001**（回撤）/ 研究里常用 **&lt; 0.0005**（年化/夏普）：Python 审稿已对 VT 做到 3–4 位，说明同输入同公式可达。把验收写成：`|Δsharpe|&lt;0.0005`、`|ΔdailyMaxDd|&lt;0.001`、`|Δcagr|&lt;0.0005`。

**最容易对不上的口径（按杀伤力排序）：**

1. **期内买入持有 vs 每日再平衡**（0.588 vs 0.593）——标量差直接飞。
2. **成交日**：信号月 `d` → 持有 `[exec(d+1), exec(d+2)]`，`EXEC_DAY=3` 即 `byMonth[m][2]`（`late-cycle/.../run.mjs`）。月末定义、半日市、Yahoo 缺日都会挪成交日。
3. **股息**：由月收益减价格涨跌反推，再按「上半月剩余交易日 / 下半月截至成交日」权重摊到日（`divDay = div/n`）。不是除息日真实分红。
4. **现金日收益**：同样按交易日分摊的月国库券，不是 overnight 复利。
5. **成本**：`COST=0.001` 乘 `|Δweight|`；**首次建仓 `prevWeight==null` 不计费**；夏普门槛常用扣费、回撤/年化常用扣费前（VT 审稿披露）。混用会「夏普对、回撤不对」或反之。
6. **样本窗**：信号月 `1973-01`–`2026-08`，净值从 **1973-02-05**（该月第 3 交易日）起——预注册曾写错过。
7. **夏普定义**：`sqrt(12)*mean(excess)/sampleStd(excess)`，excess = 期收益 − 期现金；分子分母是否用扣费收益必须锁死。

**快速定位差异的设计（应写进 1.4）：**

1. **冻结输入**：直接读 JS 研究已用的 `inputs.json` + `spx-daily.json`（或从 `dump` 导出），算 sha256，禁止 Python 侧另取 Yahoo。
2. **分层断言**（失败即停并 dump）：  
   (a) 每月 `execDay` 日期列表逐月相等 → (b) 每期 `n, div, cash, i0, i1` → (c) 无 overlay 时逐日 `weight`（应恒为档位）→ (d) 逐日 `r` → (e) 逐日 `nav` → (f) 标量。
3. **黄金对照文件**：从现有 `node docs/research/late-cycle-2026-11-25/run.mjs` 导出 `baseline-nav.csv`（日期、nav、weight、periodRet），Python 只对齐这一份。
4. **先复现 late-cycle 的 `reproduction` 块**（相对 `month-end-close` E1），再声明 0.593/−33.0% 通过。

### 3.3 多资产数据：来源、年份、坑、怎样算「核对够」

| 资产 | 可行来源 | 起止（本仓库已见 / 常识边界） | 已知坑 | 「第二来源核对」怎样算够 |
|---|---|---|---|---|
| 美股 | 已有 SPX 日收盘 + Shiller/Multpl 月股息路径 | 日线 1950+（文件已到 2026-11-24） | 价格指数+摊股息 ≠ 全收益指数；1974-07 月均价曾有席勒快照坑（`month-end-close` README） | 与 FRED SP500 抽样逐日（VT 审稿已做近期）；月收益与 `macro-significance` inputs 逐月差 &lt; 1e-6 |
| 美债总回报 | FRED **GS5/GS10** 月均收益率 → 平价久期定价（复用 `robustness/.../run.mjs` `bondReturn`） | GS5 在库：**1953-04→2026-10**；GS10 FRED 约 1953+（拉取后写入核对表） | 月均 y 压波动；固定「剩 4y11m / 类似假设」久期误差在急升息期放大；≠ Bloomberg/ICE 总回报指数 | **最低够用**： (1) 复现已有三点：1994 −4.4%、2008 +12.7%、2022 −8.5%（`robustness` README）；(2) 1990s+ 与 IEF（7–10y）/ IEI 等年收益同号且量级接近（允许数个点误差）；(3) 文档写明「收益率定价近似，非可交易指数」 |
| 黄金 | LBMA 午盘/美元金价；FRED 金价序列（如 GOLDAMGBD228NLBM 等，**具体系列 ID 需核实**）；重叠期 ETF GLD（2004+） | 可靠研究常用 **1968/1970s+**；美私人持有长期限制至 **1974-12-31** 后放开 | 1974 前制度；官方价 vs 黑市；伦敦/纽约时点；月度 vs 日度；汇率（美元计价） | (1) 主源 vs LBMA 或另一官方序列月度相关 &gt; 0.99；(2) 2004+ 年收益 vs GLD 同号近量级；(3) 预注册写死起点（建议主样本 **1975+** 或 **1968+ 并单列 1975 敏感性**） |

### 3.4 目录、版本固定、防分叉、部署

**目录：**

```text
research-py/                 # 仓库根下，与 scripts/ 并列；不进 Vite 构建
  pyproject.toml             # uv，requires-python 3.12
  uv.lock
  README.md                  # 安装：uv sync；运行入口
  engines/e1.py              # 与 JS E1 同口径净值引擎
  fixtures/                  # 从 JS dump 的 nav/exec 黄金文件 + sha256
  tests/test_reproduce_baseline.py
  alloc/                     # 第 3 步才加：风险平价权重
```

- **不要**放进 `src/` 或 `docs/research/*/venv`。
- 研究结果仍落在 `docs/research/<topic>-YYYY-MM-DD/`（PREREG + results），Python 只是计算器。

**防口径分叉：**

- 单一真源：档位与月收益继续由 Node 生产/`dump.mjs` 导出；Python **禁止**重算宏观打分。
- CI：`node .../run.mjs` 与 `uv run pytest research-py/tests` 对同一 fixture；或 Python 读 JS 写出的 `baseline-nav.csv`。
- 任何 E1 口径变更必须改 JS + Python + 更新 fixture（同一 PR）。

**本机 / Actions 复现：**

- Actions：`astral-sh/setup-uv` + `python-version: "3.12"` + `uv sync --frozen`。
- 缓存 `uv.lock`；不上传 venv。
- README 给一条命令：`uv run python -m engines.reproduce --fixture docs/research/.../baseline-nav.csv`。

**0.5 部署额度——低成本解法（按推荐序）：**

1. **Vercel `ignoreCommand`（最优、成本接近 0）**  
   在 Vercel 项目设置或 `vercel.json` 增加：仅当提交触及前端/API/配置时构建；纯 `public/data/**`、`data-raw/**` 变更跳过 Production 构建。  
   （具体 ignore 脚本逻辑：**需与当前 Vercel 计划文档核实**；Hobby 支持 skip 构建是常见做法。）
2. **合并数据提交**：多个 workflow 写入同一并发组时，改为「一日一 commit」或 artifacts 汇总再单次 push（改 `macro-snapshot.yml` / 其它 data 工作流）。注释已写明 Action 的 `GITHUB_TOKEN` push 不触发其他 workflow，但 **Vercel GitHub App 仍会跟 push 部署**。
3. **静态研究页优先 GitHub Pages**：`pages.yml` 已手动触发；核对 0.1 可先看 Pages，Vercel 恢复后再对 0.2。
4. **升级 Vercel 配额**——有效但非「低成本」；作兜底。

**建议立刻做的最小补丁（仍属计划层，本评审不改仓库）：** ignoreCommand + 数据类 workflow 减少无意义空转提交。

## 5. 不建议做的事

1. **用 `bt`/`vectorbt` 作为第 1 步复现门禁**——定制 E1 会与框架打架；失败时无法分层定位。
2. **在 Python 3.14 上直接钉量化栈**——仓库与 CI 已以 3.12 为准；3.14 二进制轮子大面积 **需核实**，无收益。
3. **未完成数据核对表就开第 3 步网格/多候选**——国债近似或黄金断点会让「压力期不更差」变成噪声。
4. **把配置库算的权重回测甩给库的默认 calendar/费用模型**——必须过同一 E1 引擎。
5. **为降波动继续堆美股择时规则**——计划已暂停；工程上再开只会增加多重比较与部署噪声。
6. **数据每次微小变更都触发 Vercel Production 全量构建**——已证明会打满额度。
7. **中国多资产与美国线并行开工**——数据短、口径另一套，稀释审查带宽。
