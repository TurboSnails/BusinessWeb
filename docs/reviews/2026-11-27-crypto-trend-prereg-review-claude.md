### 1.2 K2 建议的写死口径

建议用下面这张时间线代替现在的文字（D 为 UTC 日期，链上读数 m(D) 指 Coin Metrics 数据日 D 的 CapMVRVCur）：

```
每个执行日 E（UTC 00:00 开盘）：
  trend_on(E) = Bitstamp close(E−1) ≥ MA200(E−1)
  可用链上读数：m(E−2)
  if trend_on(E):
      目标 = 100%；count = 0；ladder = 0
  else:
      if trend_on(E−1)（趋势刚关）：count = 0；ladder = 0   # 是否从头计数，二选一写死
      if m(E−2) < 1：count += 1  else：count = 0
      新阶梯 = 3 if count ≥ 7 else 2 if count ≥ 3 else 1 if count ≥ 1 else 0
      if m(E−2) ≥ 1.25：ladder = 0；count = 0          # 退出
      else：ladder = max(ladder, 新阶梯)                 # 只升不降；计数中断不卖
      目标 = {0: 0, 1: 1/6, 2: 1/3, 3: 1/2}[ladder]
  交易：if 目标 = 100% 或 0：调到目标
        elif 当前 BTC 权重 < 目标：买到目标
        else：不交易（漂移高于目标不卖）
  趋势关闭与底部加仓同日发生时，按净额一次成交。
```

关于「趋势刚关时是否从头计数」：现稿写的是「从当日可用读数重新计数」，也就是 count 归零，即使 MVRV 已经在 1 以下待了几周，也要从 1/6 重新开始。这样写可以，但要明确。另一种读法是沿用已有的连续计数，可能一上来就到 1/2。两种读法差别很大，必须二选一。

**1.25 退出是否起作用（2018–2026 复现段的状态时间，不含任何收益）**：三个底部簇里，2018-11 那一簇趋势 2019-04-02 先重开，MVRV 2019-04-23 才 ≥ 1.25；2022-06 那一簇趋势 2023-01-13 重开，MVRV 2023-03-14 才 ≥ 1.25；只有 2020-03 那一簇是 MVRV 先到（04-06，趋势 04-29 才重开）。所以在已见数据上，1.25 退出 3 次里只有 1 次在趋势接管之前触发，K2 实际上更接近「趋势关闭期间、MVRV < 1 时分批建仓，趋势重开后并入全仓」。这不是错误，但应该写进 PREREG，免得读者以为 1.25 是主要的离场规则。还要写明 1.25 和 1/6、1/3、1/2 配 1、3、7 天这几个数是怎么来的（例如「整数化的经验值，计算前未看任何路径」）。现稿只写了「未用截图离场日期选择」，不够。

## 3. 门槛与检验方法

### 3.1 与「降低波动」目标的一致性

方向一致：以 MDD 和 σ 为主，CER 不劣作约束，杠杆不参与判定。问题在于比较对象（必须改第 2 条）：相对 B0 的风险改善主要来自敞口，只有相对同波动参考的比较才回答「择时是否优于直接少持仓」。

### 3.2 检验力（参数化粗估，未用本数据）

假设 BTC 年化波动 60%、K1 空仓 40% 的时间。K1 与 B0 的日收益差，年化标准差约 √0.4 × 60% ≈ 38%。3 年均值的标准误约 22 个百分点，97.5% 单侧下界约等于点估计减 43 个百分点。即使把方差项算上（σ 从 60% 降到 45%，CER 方差项差约 24 个百分点），K1 的统计门槛也要求很极端的前推结果。90 日区块自助法在 3 年里只有约 12 个区块，区间只会更宽。结论：**前推「通过」的检验力很低**。这不一定要改门槛，但要像 L-038 那样写进「事前预期」，免得事后把「部分成立」读成失败或侥幸。

### 3.3 区块自助与安慰剂在 2012–2017 是否有意义

- **K1**：约 5.8 年、23 个 90 日区块，由一次熊市主导。区间可以算，但信息有限。草案只在前推用统计门槛、历史只看点估计，这个分工**合理**。
- **K2**：K2 与 K1 的差只在底部期间不为零，历史段只有约一簇。自助重抽样多数抽不到或只抽到一个非零区块，分布退化，没有意义。这也是必须改第 1 条要把 K2 降级的理由之一。
- **安慰剂**：草案没有设。K1 可以加一个只报告的循环平移安慰剂（参考 L-031，平移 MA200 状态序列），K2 不需要。

### 3.4 K2 的检验力是否低到没有信息量

## 5. 建议改

1. **K1 分段检查（报告或门槛二选一）**：2012-03–2014-12 和 2015-01–2017-12 两段分别报告 MDD 与同波动 ΔCER。若作门槛，就要求两段同向。
2. **同波动参考的再平衡频率**：每日调回会持续产生成本，让参考吃亏。建议主口径改为每月调回，或者参考不计成本，每日调回只作报告。
3. **补一个下行指标作报告**：最差 30 日损失或 CVaR 5%，这对用户的「回撤」目标更直观。
4. **ETH 复现的边界**：写明 ETH 只跑 K1（底部信号只用 BTC，`DATA.md` 已经这样写）。
5. **术语**：「底部单」「趋势单」只在引用截图时使用，候选名一律用 K1/K2 加中性描述，配合必须改第 10 条。
6. **前推现金利率**：报告一个「现金按 3 个月美国国债计息」的敏感性，或者在已知信息里写明零利率对 K1 不利。
7. **`DATA.md` 的 Coin Metrics 日期口径**：「以日期 t 结尾、t+1 00:00 UTC 的 USD 定盘」读起来含糊，建议改成「数据日 t 覆盖 [t 00:00, t+1 00:00) UTC，PriceUSD 为 t+1 00:00 UTC 参考价」。

## 6. 不用改

- 主检验只用 Bitstamp BTC/USD 一个市场，历史与前推同源；ETH 和五币只在 2018–2026 做探索。这对治了事后选币，`DATA.md` 关于 point-in-time 选币「做不到」的论证充分（CMC 截面反例、CoinGecko 权限、Coin Metrics 覆盖不全）。
- 底部信号直接用 CapMVRVCur，反推的已实现价格只作展示；两者逐日核对零分歧（`count.py` 遇到分歧会报错）。
- 链上数据 t+2 开盘才使用，前推只用换日前留档的首个快照。
- 杠杆只在资金费率、成交和标记价三者共同完整的区间报告，期外不按固定费率或零补值；逐仓强平近似和数据局限都写了。
- CER 定义（γ = 3 写成 1.5 × 方差）、365 日年化、MDD 定义、自助法参数（90 日区块、20,000 次、PCG64 种子 39027）都写死了。
- 「本研究不改美股仓位规则」「通过只进研究中页签」写清楚了。
- `fetch.py` 带缓存、SHA 校验和 `--audit-only` 离线复核；原始数据只留本机，`SOURCES.md` 记下了每个响应的 URL、时间和哈希。
- 结论分级里「若注册未能按时冻结……须重登记起点」这一条很好，建议保留。
