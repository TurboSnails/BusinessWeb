# 牛熊周期自动数据与周度留档

入口：投资 → 宏观温度 → 牛熊周期，`/monitor?tab=market-cycle`。日常查看六维证据、数据质量问题及分层观察；“重新读取”读取发布快照。

## 已实现的自动链路

`scripts/market-cycle-update.mjs` 顺序执行价格、事实、宽度采集，单个失败仍继续，最后生成 `public/data/market-cycle-report.json`。宽度首次建库会有界续采，最多12轮、每轮40请求、总480请求、8分钟，达到三市场合格条件、无进展或熔断时提前结束。不依赖用户打开页面，不调用大模型打分，也不自动交易。

- 腾讯完整周/月价格；MACD、RSI和BOLL仍合计一维。
- 中证官方沪深300 PE与中国10年国债同日交集，5年滚动简化ERP z-score，至少1000交集点且覆盖窗口起点；当前首次实测1212点。公式为 `100/PE − 国债收益率(%)`，z-score使用样本标准差。国债分页每页500；不拿500条冒充5年。
- 恒指及恒生科技官方月PE：当前文件只有12个月，无5年分位，显示原值并保持判断缺失。
- 两市融资买入额原值；尚未核定同覆盖成交额分母，不生成融资占比或资金票。港股接入东财南向汇总通道006的最近20个交易日净买入，原始百万元人民币除100换算亿元；它是全港股背景，仍缺本指数完整周与前52周同口径成交额，不单独生成资金票。
- Yahoo离岸CNH（检查symbol及currency，不用CNY替代）和FRED实际HKD/USD；汇率原值作为背景，不声称已实现20周汇率方向判断。
- 上交所6只ETF份额白名单，按代码、简称和日期校验；不是全市场份额合计，不据此认定资金底背离。
- 宽度模块已接沪深300官方300只成分，以及恒生指数公司实时成分接口（校验指数身份、官方计数、逐行代码与快照日期）。名单快照日期与生效变更日期分开表述。A股使用腾讯前复权日线，港股接东财显式`fqt=1`日线，校验返回市场与代码；两者使用独立缓存，旧港股未复权缓存不能计票。只有当期观测名单、新鲜价格、当前及4周前合格覆盖均满足95%才能计票。指数成分宽度不称“全A股宽度”。缺少名单或行情、历史不足、请求失败会分别说明。

中证`peg`沿用项目官方滚动PE接口。国债`EMM00166466`映射核对 [AKShare自身实现的明确rename](https://github.com/akfamily/akshare/blob/main/akshare/bond/bond_em.py)，数据为东财转载，非中债直连。港股来源为[恒指官方xlsx](https://www.hsi.com.hk/content/dam/wpb/hsil/index_operation/historical_pe/en_hk/hsi/hsi.xlsx)与[恒生科技官方xlsx](https://www.hsi.com.hk/content/dam/wpb/hsil/index_operation/historical_pe/en_hk/hstech/hstech.xlsx)。

## 事实与时点

`market-cycle-auto.json`的事实包含指标ID、市场、原值、单位、观测日期、真实发布时间（未知为null）、首次发现、抓取时间、公开来源、频率、observed/proxy/backfilled与说明。同指标/市场/观测日唯一，同值重抓保留首次发现，序列最多60点。前端取最新事实；日/周/月有效期分别14/21/75天。失败不刷新旧事实日期，未来或过期事实不计票，代理不得静默转换为精确证据。

`availableAt=null`不代表历史当天可交易；首次发现不回填成原始发布日期。这些快照用于当前观察与从现在开始的留档，不能用于宣称已完成PIT历史回测。

## 自动、人工与影子规则

默认合格自动证据优先，缺失时使用有效人工补录。逐维可明确选择“本次使用人工覆盖”。保存复盘时冻结自动事实、宽度快照、人工输入、覆盖选择、最终六维证据和规则版本；旧备份保持兼容。

现有观察汇总版本为`cycle-observation-v1.1-auto`。`cycle-shadow-v2`同时输出赔率区域、趋势状态、风险约束与数据质量：

- 低估可以与趋势防守并存；技术风险立即触发防守复核。
- 正向技术需连续两份真实相邻完整周价格确认才进入上行观察；同周重跑替换当前周记录，不增加次数。旧价格跨周沿用也不能增加次数；漏周重置。
- 已确认上行遇中性，连续两份完整周才退出上行观察；风险仍即时生效。
- 少于4个有效维度，或缺估值/宽度时，质量为证据不足，风险约束暂停提高风险。该规则只观察，不给个人固定仓位。

自动周报最多52周，每条保存决策时点、规则版本、输入SHA-256、各市场证据及新旧状态。输入原文件随Git数据提交留存；没有长期历史时不补造历史状态。页面当前读数与已归档周报分别标识，本机补录不改自动周报。

## 运行与运维

- 首次环境准备：Python虚拟环境内执行 `python -m pip install -r scripts/requirements-market-cycle.txt`（xlrd 2.0.2用于官方XLS；港股XLSX解析使用标准库）。如需指定解释器，设置 `MARKET_CYCLE_PYTHON`。
- `npm run market-cycle:update`：采集并留档全部周期数据。
- `npm run market-cycle:prices`：只刷新周/月价格。
- `npm run market-cycle:report`：用已发布输入重新生成本周留档。
- `node --test scripts/market-cycle-*.test.mjs`：脚本、契约、容错和留档测试。
- `npm test -- src/features/market-cycle`：前端、规则、恢复与覆盖测试。

`.github/workflows/market-cycle.yml`每12小时执行有上限的增量采集，也可手动触发；实现文件推送会触发云端采集。宽度单轮总请求硬上限40、并发最多2，未抓/最旧优先；更新入口最多续采12轮、总480请求、8分钟，剩余时限传入子进程硬超时，失败或无进展会停止。0预算可离线重算；统一真实交易日比较，不混合缓存日。逐股日线缓存使用actions/cache，不将全量日线入Git。只发布紧凑事实、名单、宽度与周报。所有数据发布流程共用并发组，推送冲突会有限重试；有效的部分数据和质量问题一起发布，再触发Pages部署。缓存由GitHub保留策略管理，丢失后重新分批初始化。

仍待验证：稳定的多周云端可达与维护成本、完整同口径融资比例、港股长期估值、历史成分PIT、背离与天量识别、多周期/费用后/样本外/简单基准比较。已上线采集与影子观察，不代表完整策略或收益验证完成。
