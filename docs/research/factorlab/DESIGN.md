# 因子研究基建（factorlab）设计

建立于 2026-11-26；同日经一份独立设计评审（子 agent）修订第三至六节：锁箱固定区间与终身预算、数据层强制、截面验证与前推层、主口径改市值加权并剔除微盘、次日开盘执行、成本表更正。用户决定长期做因子挖掘与回测，覆盖 **A 股、港股、美股**。本文是各模块的共同约定；代码在 `research-py/factorlab/`。

## 一、为什么要先搭基建、而且要带「护栏」

因子挖掘本质是大规模试错：试得越多，碰巧好看的越多。本项目在美国 1973–2026 年的数据上已经比较过约 90 种写法（`docs/research/LEDGER.md`），L-028 审计显示优势里有一部分可能来自挑选。所以基建的第一原则是：**每一次评估都自动记账，留一段谁都不能偷看的数据，确认检验必须先预注册。** 工具好用以后试错会变便宜，护栏必须先于工具存在。

## 二、模块

```
research-py/factorlab/
  schema.py        数据约定（列名、类型、幸存者偏差等级）——各方共用，改动要同步
  store.py         本地数据仓库读写（parquet），load_panel 出宽表
  sources/         数据源适配器（每个市场一个模块，只负责「下载 → 写成约定格式」）
    http.py        共用 HTTP：限速、重试、断点续传、curl 兜底
    cn.py          A 股（东方财富日线 + 沪深北交易所证券表 + 已退市名单）
    hk.py          港股（东方财富港股日线 + 当前证券表；没有退市股 → 等级 B）
    us.py          美股个股（东方财富 / Yahoo 日线 + 当前证券表；等级 B）
    kf.py          Ken French 组合库（美国与国际，组合级，等级 C）
    sec.py         SEC EDGAR 财报（点时：按申报日生效；需环境变量 SEC_USER_AGENT，未设置则跳过）
  calendar.py      交易日历、月末调仓日
  universe.py      点时股票池（已上市满 N 天、未退市、非停牌、流动性门槛；A 股剔除涨跌停无法成交）
  registry.py      因子注册表：@factor 装饰器，带元数据（名称、所需字段、回看期、市场、说明、版本）
  factors/         因子定义（纯函数：面板 → 调仓日 × 代码 的因子值，只用调仓日收盘前可得的数据）
  preprocess.py    截面去极值（MAD）、标准化、行业 / 市值中性化
  evaluate.py      IC / RankIC、ICIR、分组收益、多空与「做多前 20% 对股票池」、换手、衰减
  backtest.py      只做多、月度调仓、按市场的成本与交易约束（A 股印花税、涨跌停、停牌）
  guard.py         护栏：试验登记簿（自动记每次评估）、锁箱（留出期数据默认不可见）、多重检验校正
  report.py        报告（JSON + Markdown）
  cli.py           命令行：fetch / build / eval / ledger / unseal
```

## 四、护栏（guard.py，评审后修订）

数据分四层（每个市场各自一套）：

| 层 | 范围 | 用途 |
|---|---|---|
| 探索区 | 2023-10-31 以前，按 `sha256(code)` 取 70% 的证券 | 随意试，自动记账 |
| 截面验证 | 同期另外 30% 的证券 | 进预注册前必须在这里方向一致；挡住「只对少数股票成立」，挡不住时间上的运气 |
| 锁箱 | **固定**为 2023-11-01 至 2026-11-30，全部证券 | 确认检验；每个市场终身候选预算 24 个，**按季度批量解封**，批内 Holm 校正；预算用完即宣布锁箱作废 |
| 前推记录 | 2026-12-01 以后 | 所有预注册过的候选（不论通过与否）冻结代码哈希、按月记账；只作淘汰开关（例如 24 个月 t < −1 撤下），不当证明 |

1. **试验登记簿**：`research-py/factor-ledger/{market}.jsonl`（进 git），每次评估自动追加，不能关闭。每条记录：时间、git 提交与是否有未提交改动、因子源码哈希与参数、数据快照哈希（MANIFEST 的 sha256）、股票池 / 预处理 / 加权 / 成本 / 执行口径、样本区间与所在层、月收益序列文件路径（`factor-ledger/series/`）、父试验与因子族、动机（文献 / 挖掘）。批量公式挖掘时每个表达式计一次。
2. **锁箱在数据层强制**：`store` 的读接口默认截掉锁箱与前推区间；前瞻收益按**结束日**截断，并在边界留 1 个月间隔（embargo）。只有 `unseal(market, batch_id, prereg_commits, candidates)` 能读，解封记入 `factor-ledger/unseals.json`；LEDGER 规则 4 的「用一次即作废」对锁箱整体适用，按批次计数，不按预注册份数。候选在解封时冻结为（因子名、源码哈希、参数哈希、配置哈希），确认评估必须完全一致、每个候选只确认一次（见第八节）。
3. **多重检验**：DSR 的试验次数用登记簿按收益相关聚类后的「有效试验数」（只报告）；PBO 用 CSCV（需要登记簿里的收益序列）；锁箱确认的门槛是方向一致且幅度不低于样本内收缩估计的一半，统计显著性只报告（36 个月功效低，预注册里必须写功效计算）。
4. **进预注册的前置条件**：截面验证方向一致；对规模、价值、动量、反转、低波、换手（A 股可用 CH-3）做 spanning 回归仍有增量；与已有因子秩相关 > 0.7 的归为同一族，只取一个代表。
5. **跨市场复现**可作替代确认：A 股发现的因子拿到港股大盘、Ken French 国际组合上检验。
6. **只做多、可执行**：主口径见第五节；多空收益只报告。

## 五、评估口径（评审后修订）

- **主口径**：剔除市值最小 30% 后，做多前 20%，**市值加权**，对同一股票池市值加权；同时报等权、市值三档分别的结果（A 股等权结果基本由微盘与壳价值决定）。
- **执行时点**：信号用调仓日收盘数据，成交默认在**次日开盘**（需要复权开盘价 `open_adj`）；A 股次日开盘一字涨停买不进、一字跌停卖不出，停牌持有到复牌；持仓股退市时补一个退市收益（默认 −100% 的保守值，可配置）。
- **重叠期限**的 t 值用 Newey–West；A 股按 2017 年前后、2024 年前后分段报告（锁箱含 2024 年初微盘崩盘）。
- **股票池**：退市过滤按「退市日晚于 t」；流动性门槛只用 t 之前的数据；剔除上市不满 120 个交易日或尚未开板的新股；港股、美股只用每期流通市值前 500、股价 ≥ 1（当地货币）的证券。用当前行业做中性化是轻度前视，要写明。
- **容量**：报持仓占日均成交额的比例。

## 七、路线

1. v0（2026-11-26）：上述模块、合成数据测试、各市场小样本试下载与数据审计。
2. v1：全量下载（A 股含退市约 5,500 只、港股约 2,600 只、美股约 6,000 只，限速下载，分批进行），经典因子复现（规模、动量、反转、低波、换手）作为引擎校验。
3. v2：基本面因子（A 股财报、SEC 财报，都按公告日 / 申报日点时生效）。
4. 之后：每个候选因子按「探索 → 预注册 → 锁箱确认」走，通过的放「通过检验」页，不自动进综合策略。

## 八、2026-11-26 代码审查后修复

同日一份独立代码审查（复现脚本已转为 `research-py/tests/test_factorlab_review.py` 里的回归测试）发现以下问题，均已修复：

1. **衰减 h ≥ 2 前视**：原来先用每期各自的股票池掩码再累计，等于以「后几期仍在池内」为条件。现在先按层截断、再累计，最后只用形成日的股票池掩码（`evaluate.decay_table`）。
2. **forward 模式不要凭证**：数据层 forward 必须给出已核验的预注册提交；没有本市场有效解封凭证时删掉锁箱区间的行（只给锁箱前与锁箱后），直接读数据层的 forward / confirm 记一条 `data_access` 事件。
3. **锁箱 / 登记簿可调包**：`Lockbox()`、`TrialLedger()`、`evaluate_factor`、`unseal` 不再接受路径或实例参数，环境变量 `FACTORLAB_LEDGER` / `FACTORLAB_LOCKBOX` 停用（设置了直接报错）。唯一例外是显式命名的测试钩子 `guard.set_test_overrides(...)`：每条登记记录写 `lockbox_path`、`ledger_root`、`test_override`；钩子启用且 store 指向仓库数据目录时，数据层拒绝 confirm / forward，其他模式截在包内锁箱起点以前——换掉锁箱配置也读不到仓库里的锁箱数据。`store` 与 `guard` 用同一个包内 `lockbox.json`。
4. **解封后可无限挖掘**：`unseal` 的候选改为 `evaluate.candidate_spec(...)` 生成的（因子名、源码哈希、参数哈希、配置哈希；配置含股票池 / 预处理 / 加权 / 执行 / 成本等）；confirm 必须完全一致、不接受 DataFrame 因子、每个候选只能成功确认一次（第二次拒绝并以 `status='refused'` 记账；确认评估全程持登记簿文件锁，并发确认也只有一次能通过；报错中断的不算用掉）。预注册必须是十六进制提交哈希（不接受 `HEAD` 等符号引用），且该提交里有 `docs/research/` 下文件名含 `PREREG`、列出全部候选名的文件（`git show` 核验）。`unseal` 去掉 `now` 参数，用模块级时钟 `guard._now()`。
5. **试验去重不含源码**：「写法」身份 = 因子名 + 源码哈希（DataFrame 因子为内容哈希）+ 参数哈希 + 配置哈希；有效试验数、DSR、PBO 不再把同名不同内容的试验合并。
6. **证券表泄露锁箱**：数据层按可见上界删改证券表：上市日 ≥ 可见上界的行删掉，退市日 ≥ 可见上界（或落在被删区间）的改为空、状态改为 listed。
7. **MAD = 0 抹平截面**：MAD 为 0 时改用标准差折算的宽度（n × 0.6745σ），标准差也为 0（真常数）才不截；zscore 只在整行真为常数时置空。
8. **并列值口径不一**：分组（`quantile_labels`）、前 1/n 换手与回测选股共用 `backtest.select_top`：值从大到小、并列按 `sha256("tie:"+代码)`，与列顺序无关；名额 = round_half_up(q × k)。
9. **空股票池静默通过**：层内平均股票池 < `min_universe`（默认 30）或因子覆盖率 < `min_coverage`（默认 10%）时报错并记 `status='error'`。缺市值的调仓日（美股目前全缺、港股早年缺），`UniverseSpec.mcap_fallback='amount'` 改用 t 之前 20 日成交额中位数排序做前 500 / 剔除最小比例（股价 ≥ 1 照旧），主口径加权改用成交额中位数代理；实际用了哪种写在登记记录的 `universe_applied` / `weighting_applied`，报告里注明。
10. **70/30 只在评估层**：数据层 `load_market` / `guard_panel` 在 explore / validate 只返回本层证券（面板与证券表）。底层工具改为内部名（`evaluate._forward_returns`、`_ic_series`、`backtest._backtest`、`_backtest_vs_universe`），研究只走 `evaluate_factor`。

另：报告措辞（成交时点、前百分之几）按本次口径生成；分组 / tmu 的「股票池」基准改为全部入池证券（不论因子是否有值），与回测基准一致；登记簿追加与 `unseals.json` 读改写在目录级文件锁（`fcntl.flock`）内完成。性能：成交额 20 日中位数只在需要的日子算一次并在股票池、滑点、容量、加权代理之间共用，可空布尔转换改为 numpy，IC 向量化；合成 5,000 只 × 5,040 日、动量因子 + 市值中性化 + 两种加权回测，单次评估由约 60 秒降到约 13 秒（探索层 3,500 只）/ 17 秒（5,000 只全部）。

未改：绕过引擎直接 `store.read_prices(raw=True)`（或读 parquet）拿锁箱数据无法从代码上阻止，只能靠登记簿与评审；测试钩子下在合成面板或临时数据目录上仍可解封、确认（沙盒，记录带 `test_override`），不会碰仓库数据。
