# 第五轮因子挖掘（R5）：盈余惊喜（A 股、美股）——计划与晋级规则

写于 2026-11-27，在写任何盈余惊喜因子代码之前提交。只用文献里已有的定义（动机 `literature: R5`），不做公式搜索。

## 为什么做这一轮

R1–R3 测过的都是「水平」类特征（估值、波动、换手、盈利能力），盈余公告后的漂移（PEAD）是另一类信息：市场对新财报反应不足。文献：Bernard–Thomas（1989）标准化未预期盈余 SUE；Jegadeesh–Livnat（2006）营收惊喜 SUR；A 股上也有大量 PEAD 证据（如 Truong 2011、各家券商的 SUE 因子报告）。

## 因子（4 个，各计一次试验）

| 编号 | 市场 | 因子 | 定义 | 方向 |
|---|---|---|---|---|
| E1 | A 股 | cn_sue | 单季归母净利润 X（由累计值还原）；SUE = (X_q − X_{q−4}) / σ，σ = 最近 8 个「同比差」X_{q−j} − X_{q−4−j}（j = 0…7）的标准差，至少 4 个有值；q = 调仓日已公告（公告日早于调仓日）的最新季度 | + |
| E2 | A 股 | cn_sur | 同上，用单季营业收入 | + |
| E3 | 美股 | us_sue | 同 E1，用 SEC NetIncomeLoss 单季（10-Q 单季直接取，第四季 = 年报 − 前三季累计）；可用日 = 申报生效日 | + |
| E4 | 美股 | us_sur | 同 E3，用营业收入（与已有美股基本面相同的科目回退顺序） | + |

共同细则：最新季度的期末距调仓日超过 200 天的（没有按时出新财报）记缺失；σ = 0 记缺失；分子分母都用同一币种原值（不除股本）。

## 晋级规则

- **A 股**：R1 规则（主口径 = 剔除最小 30%、前 20% 市值加权）。另外报告 R4 的「中小盘等权」口径数字；如果主口径没过而等权口径满足 R4 第 1 关全部条件，也可以按 R4 规则进第 2 关。因为给了两次机会，**两种口径的超额 t 门槛都从 2 提高到 2.25**（≈ 两次检验的 Bonferroni）。
- **美股**：R1 规则（市值前 500 里前 20% 市值加权，样本从 2011-08 起，同 R1 美股基本面）。美股价格是等级 B，第 4 关要交叉验证，而 Ken French 库没有盈余惊喜组合，所以**美股最多到第 3 关**，结果作为待数据补齐的记录，不进锁箱。
- 第 3 关基准：A 股同 R1（规模、1 月反转、60 日波动、20 日换手）；美股 Ken French 五因子 + 动量。
- 第 4 关同 R1：每市场第一批不超过 4 个候选（与 R4、R6 合计），预注册后 2026-12 确认。

## 测试要求（跑之前写好）

扰动未来数据 / 截到当日重算无前视；公告日当天不可用、次日起可用；单季还原与手算一致（含第四季）；σ 的最少样本规则；200 天陈旧规则。

**实现口径（写在跑之前，没有看收益）**

- A 股：X = 单季归母净利润（`net_income_parent`）/ 单季营业收入（`revenue`）。累计值还原：一季度 = 一季报累计；二、三季度 = 本期累计 − 上一季累计；**第四季 = 年报 − 三季报累计**。每个月末 d 同一（代码，报告期，科目）取 avail_date ≤ d 的最新版本（avail_date = 公告日之后第一个交易日，所以「公告日早于调仓日」⇔ avail_date ≤ d；公告当天不可用、下一个交易日起可用）。两期累计任一缺失 → 该季单季值缺失。
- q = d 时已生效的该科目最新报告期（只看季末报告期），不往回退：q 的单季值算不出来就为空。SUE = (X_q − X_{q−4}) / σ，σ = j = 0…7 的同比差 X_{q−j} − X_{q−4−j} 的**样本标准差（ddof = 1）**，至少 4 个有值（包括 j = 0 本身）；σ = 0（同比差全相同，按相对 1e-9 以内判定，用来吸收浮点求均值的舍入）→ 空；q 的期末早于 d 超过 200 天 → 空。前一年同季等用到的都是 d 时已生效的最新版本（包括之后报告里的重述数）。
- 美股：X = SEC NetIncomeLoss / 营业收入的单季值。在每家公司每个知识时点 t（任一科目的申报生效日；生效日规则同 R1：美东 16:00 前受理当天、之后下一工作日，没有受理时间按申报日 + 1 个工作日）用截至 t 已生效的快照还原单季，规则与 `sec.quarterize` 相同：直接披露的 3 个月期间优先；否则同一财年起点的累计值相减（Q2 = H1 − Q1、Q3 = 9M − H1、**Q4 = 年度 − 9M**，两期末相差 80–100 天）。月末 d 取 t ≤ d 的最新状态，200 天陈旧照查。
- 美股季度对齐：美股财年季末不一定是自然季末（52/53 周财年、非日历财年），季度按「期末 − 15 天」所在的自然季度归档，X_{q−4} 就是往前第 4 个归档季度；同一归档季度有两个期末时取较晚的。q = 快照里该科目流量期间（3/6/9/12 个月）的最晚期末所在的季度。
- 美股收入科目（**计划写的「与已有美股基本面相同的科目回退顺序」不存在**：已有美股基本面字段没有用收入）：改用 SEC 适配器 `sec.DEFAULT_CONCEPTS` 里的顺序 Revenues → RevenueFromContractWithCustomerExcludingAssessedTax → SalesRevenueNet，**逐季**取第一个有值的科目（2018 年 ASC 606 前后公司常换科目，逐季才能衔接同比差）；q 取三个科目里最晚的期末。这一条在跑之前定下，跑之后没有改。
- 不改任何已有字段的值：A 股新字段另算、另缓存（缓存键含 `sue-cn-v1`），只有请求这两个字段时才算；美股另建 `surprise.parquet` 与 `SURPRISE_MANIFEST.json`，不动 `events.parquet` / `MANIFEST.json`。两个模块的 `snapshot()` 都没改，已有因子的数据快照哈希不变（测试核对）。护栏同已有基本面：A 股先删 avail_date 不早于可见上界（或落在被删区间）的财报行再算；美股删掉知识时点 t 不早于可见上界的状态行（每行只用生效日 ≤ t 的数据）。
- 美股状态表：5,027 个 pit 文件 → 181,870 行、4,707 家公司、0 个错误；`surprise.parquet` sha256 `4971fa54f3edda66…`，pit 指纹 `72c98dfcf8ea03ec`（与 `events.parquet` 的构建来源相同）。

### 第 2–3 关判定细则（第 1 关算完之后、跑任何验证区评估之前写定）

第 1 关里 cn_sue、cn_sur 两种口径都过了（数字见上表），计划没有写「两种口径都过时第 2 关按哪一种判」，所以事先固定如下，不看验证区结果再改：

1. 每个因子只跑一次 `--mode validate`（默认口径），同一次评估里同时有主口径（市值加权）与等权的数字。
2. **主口径路径**（R1）：第 2 关 = 验证区 RankIC 方向一致且 NW t ≥ 2、主口径超额方向一致；第 3 关 = 探索区 `tmu_cap` 对 R1 四个基准的探索区 `tmu_cap` 序列 spanning，截距 NW t ≥ 2。

### 候选与结论

### 问题与局限（照实记录）

1. **计划里美股收入「与已有美股基本面相同的科目回退顺序」没有对象**：已有美股字段不用收入。改用 `sec.DEFAULT_CONCEPTS` 的顺序逐季回退（见实现口径），跑之前定下；不同科目的口径可能不完全一致（例如 Revenues 含、RevenueFromContract… 不含某些项目），换科目的那几季同比差会带入口径差。美股没过第 1 关，这一条不影响结论。
2. 美股季度按「期末 − 15 天」归档：季末落在 1/4/7/10 月 8–22 日附近、且在两侧来回漂移的公司会错档（少见）；财年改变的公司会有断档，σ 样本不够时为空。XBRL 2009 年起才有，2011–2012 年覆盖较低。美股是等级 B（只含当前上市股）。
3. A 股不用业绩预告、业绩快报：惊喜按正式定期报告的公告日计，比市场实际得知晚（偏保守，可能低估惊喜的即时信息，也可能把一部分「预告后漂移」算进来）。
4. A 股退市股的财报（新浪）多数版本晚一年才生效（R2 已记录），在 200 天陈旧规则下基本为空，所以这两个因子在退市股上近似「只用当时上市股」。主口径剔除最小 30% 且市值加权，退市股权重很小；等权口径影响可能大一些，未单独量化。
5. 登记簿的源码哈希只覆盖 `factors/surprise.py` 里的因子函数，不覆盖 `fundamentals_cn.surprise_fields` / `fundamentals_us.firm_surprise`；两个模块的 `snapshot()` 故意没改（为了不改已有因子的数据快照），所以 `data_snapshot` 也区分不出盈余惊喜计算的版本（A 股缓存键里有 `sue-cn-v1`，美股状态表 sha256 记在上面）。写预注册时要另外冻结 `fundamentals_cn.py` 的哈希（或其提交）。
6. 本轮 6 条记录的 `git_dirty = true`（代码未提交，提交基点 `64f65309`）；预注册前须先提交代码，并核对提交后的因子源码哈希仍是 `5e60044b630a`（cn_sue）、`e4013d23f458`（cn_sur）。
