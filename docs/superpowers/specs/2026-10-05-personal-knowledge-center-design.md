# 个人知识中心：集成设计草案

状态：用户已确认本地工作台范围并授权自行计划、持续执行。第一版与本地 MCP 已实现并验证；云阶段尚未接入。

## 目标

在现有 BusinessWeb 顶层导航增加“个人知识中心”，路由 `/knowledge`。Obsidian 和网站共用用户控制的 Markdown 文件；未来多个 AI Agent 通过同一个知识服务访问，数据库只承担可重建索引。优先低成本、可迁移和渐进扩展。

用户已明确最终架构方向。本草案建议第一版采用本地工作台；首次实施前需确认这一范围。Vault 路径尚未提供，第一版通过服务端配置指定，不能把个人笔记默认加入公开网站仓库。

## 集成方案比较

1. 推荐：真实 Markdown + 本地知识服务 + 网站新标签。能与 Obsidian 共享数据，沿用现有本地估值服务的运行模式，无需先配置云服务。
2. 仅新增架构介绍页面。实现简单，但无法积累或搜索真实知识，不满足个人数据中心的目标。
3. 同时实现 Supabase、R2、远程 MCP 和自动整理。最终能力完整，但需要部署、身份验证、同步和模型配置，不宜作为首批实现。

## 第一版页面

- 顶层“个人知识中心”入口，桌面与移动导航均支持当前页高亮。
- 左侧目录和笔记列表；目录采用用户给出的 Inbox、Investment、AI、Development、Projects、Life、Attachments、Templates 结构。
- 中间显示与编辑 Markdown，支持新建笔记和保存。
- 搜索标题、路径和正文，展示命中来源。
- 每日 Inbox 使用 `00-Inbox/YYYY-MM-DD.md`，支持追加想法；服务不可用时保留编辑内容并显示失败，不能显示已保存。
- 关联区域展示解析得到的 wikilinks、反向链接和未解析链接。第一版不引入向量搜索或大型知识图谱。
- 未配置 Vault 或本地服务不可达时显示明确的连接状态和启动说明；公开部署页面不展示私人内容，也不伪造已连接状态。

## 数据与服务

新增独立知识模块和绑定回环地址的 Node 本地知识服务，复用项目已有技术栈。浏览器通过开发代理访问服务；服务端读取配置中的绝对 Vault 路径。用户可以指定现有 Vault；新 Vault 初始化只创建缺少的目录，不覆盖已有笔记。

Markdown 文件为唯一笔记正文来源。附件先保留在 Vault 内，相对引用继续有效。Git 由用户为私人 Vault 单独管理；网页保存不自动提交或推送。

知识模块提供列出、读取、搜索、新建、保存和追加操作。所有路径限制在配置的 Vault 内，拒绝路径穿越与符号链接越界。写入检查内容版本，若 Obsidian 或其他 Agent 已修改文件则返回冲突并保留用户草稿；使用原子替换，避免留下半写入文件。只处理 Markdown，排除 `.git`、`.obsidian` 和无关隐藏目录。

链接索引从文件重建，支持 `[[笔记]]`、`[[目录/笔记]]`、别名及标题片段；重名不能静默连接错误文件。页面刷新或重新查询能读取 Obsidian 的外部修改。

本地服务检查访问来源和本地访问凭据，防止其他网页直接写入个人 Vault。页面配置不包含 Supabase service-role key、R2 密钥或其他云端秘密。

## 后续扩展

第二阶段：在同一个文件服务边界之上增加本地 stdio MCP，提供搜索、读取、关联、新建与追加工具，供支持该连接方式的 Agent 使用。写入继续执行路径与版本检查。

第三阶段：增量索引到 Supabase PostgreSQL/pgvector，记录文档路径、哈希、分块、embedding 模型及维度、关系；处理修改与删除。索引可清空重建。Embedding 方案在这一阶段再定。

第四阶段：R2 附件存储与恢复流程，保留附件清单、稳定逻辑引用及本地副本/缓存策略，避免把过期签名 URL 作为笔记中的永久引用。

第五阶段：受认证保护的远程 MCP 与云端可访问的权威文件服务，供远程 Agent 使用。本地磁盘不能直接作为公开静态网站或远程 Agent 的文件接口；需要明确文件同步、并发和访问权限后再开放。自动 Inbox 整理先产生可审阅建议，再执行移动和改写。

## 预计代码边界

- `src/data/siteMap.ts`、`src/App.tsx`：导航与路由。
- `src/pages/KnowledgeCenter.tsx`：页面入口。
- `src/features/knowledge/`：页面组件、API 调用和编辑状态。
- `server/knowledge/`：Vault 文件服务与 HTTP 入口。
- 启动脚本、Vite 代理、类型检查配置和本地使用说明。

现有研究与估值报告第一版不自动批量迁移；后续通过显式导出 Markdown 接入。

## 验收

1. 桌面与移动导航可进入新页，原有导航和路由正常。
2. 在临时 Vault 新建、编辑、搜索并读取真实 Markdown；Obsidian 修改后能重新读取。
3. 每日 Inbox 多次追加不覆盖原文，写入失败保留草稿。
4. 外部修改触发冲突，不能覆盖他人更新；路径穿越和越界符号链接被拒绝。
5. wikilinks 与反向链接来自真实笔记，重名与缺失目标明确呈现。
6. 未连接时显示真实状态；私人笔记不进入网站构建产物。
7. 运行相关服务测试、页面集成测试、覆盖新增模块的类型检查和生产构建。

用户已确认推荐的本地 Markdown 工作台并授权自行计划、持续执行。默认使用独立私人 Vault；现有 Obsidian Vault 可通过环境变量指定。
