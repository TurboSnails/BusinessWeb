# 使用现有服务器同步 Obsidian

## 用户目标

沿用项目自己的云端服务，让同一份知识在多台电脑的 Obsidian 和知识网络网页中保持一致。新电脑连接后取回现有笔记，本地编辑自动同步；不要求购买 Obsidian Sync。

## 已确认的现状

- Vercel `/api/knowledge` 连接现有 Supabase。
- `businessweb_knowledge_head` 保存当前 revision/generation，`businessweb_knowledge_notes` 保存 Markdown 正文、版本和关联。
- `scripts/knowledge-cloud.mjs` 上传完整快照，以 expectedRevision 原子发布；当前没有下载和自动合并。
- 网页和远程 MCP 为只读。
- 本机 `BusinessWeb/.local/SecondBrain` 是本次新建的空目录，不能当作已经恢复的数据。
- 未通过认证读取生产资料库，因此生产笔记数量和完整性尚未验证。

## 推荐方案及替代方案

推荐在 Obsidian 中安装项目自己的同步插件，调用现有 Vercel API，由 Supabase 保留共享版本。这样每台电脑都能在应用内配置连接，无需每次另开终端。

桌面后台 Node 同步程序也可复用现有文件模块，但需要额外安装运行环境及管理后台进程。改用另一套同步数据库会增加运维和数据迁移，此次不采用。

## 数据与接口

共享资料库使用服务端稳定身份，独立于本机目录的哈希身份。保留现有本地写入保护；插件对 Obsidian 文件操作使用自身同步状态，上传数据转换为共享身份。

下载增加固定 generation 的分页清单与正文接口。客户端一次同步期间绑定同一 generation，避免混合两个快照；校验正文 SHA-256、路径和页数。下载失败不改变同步基线。

上传沿用批量暂存和原子发布。服务端增加同步专用凭据，具备读取和发布权限；网页和 MCP 原有只读凭据保持只读。Supabase 管理密钥仅保存在服务端。

服务端校验每篇正文哈希、共享身份、唯一规范路径、体积限制，以及新快照的引用图。发布使用 expectedRevision，过期返回 409。已发布快照不可修改；旧版保留供恢复。支持空资料库和完整删除，不能继续以“至少一篇笔记”为发布条件。

## 客户端行为

插件提供服务器地址、同步凭据、连接测试、立即同步、上次同步状态和错误提示。凭据仅保存在本机插件设置中，不传给网页或输出到日志；明确该设置文件包含凭据，排除在同步范围之外。

首次连接空仓库时下载服务端当前 Markdown。已有本地内容但没有同步基线时，保留双方数据；相同路径不同内容作为冲突，不能直接覆盖。首次取回完成前禁止发布空本地快照。

连接后立即同步，定时检查远端，并在本地文件变化后防抖同步；同一客户端只允许一个同步任务运行。离线继续编辑，恢复连接后同步。远端更新通过 Obsidian Vault API 应用，避免再次被当作用户的新改动。

首版同步 Markdown 正文和目录。当前云端没有图片/PDF 原件，附件同步另列阶段；客户端必须显示“仅笔记同步”，不能把设备迁移描述为完整资料库迁移。

## 合并、删除与恢复

客户端保留上次成功同步的基线，按路径比较基线、本地和远端内容哈希。仅一方变化则采用该方，两方变化且内容相同直接接受。

两方不同修改或删除与编辑冲突时，保留正文副本供用户处理，并显示冲突，不静默覆盖。重命名按删除加新建处理，同样保护删除与编辑冲突。客户端本地删除不得通过整体快照覆盖消除另一设备新建的笔记。

发布被其他设备抢先时重新读取最新版本并重新合并，有限重试；仍冲突则提示稍后同步。网络超时后先查询 head 确认是否已发布，再决定重试。断电或中断恢复依赖事务日志和原子更新的基线，不能把未下载完成的版本标记为已同步。

路径拒绝穿越、隐藏目录、绝对路径、反斜杠、控制字符及符号链接；对 macOS/Windows 大小写冲突和 Unicode 规范化冲突进行检测，报错后保留双方内容。删除进入可恢复位置，保留服务端旧快照。

## 验收

1. 新设备连接现有服务端，自动取回真实笔记，Obsidian 能打开并解析链接。
2. A 修改后 B 自动获取，网页在新版本发布后展示相同正文和引用。
3. A、B 修改不同笔记不会相互覆盖；修改同一篇保留冲突内容。
4. 首次空仓库不会清空生产数据；离线、超时、发布冲突和进程中断后可继续同步。
5. 删除/编辑、重命名、大小写路径冲突有明确结果且可恢复。
6. 越权读取或发布被拒绝；只读 MCP 仍不能写入。

先使用临时数据库和两个临时仓库验证；生产阶段先读取并备份当前快照，再执行经过验证的迁移、部署和首次下载。自动上传只在成功恢复和建立基线后启动。

## 待用户确认的范围

默认先覆盖桌面电脑和 Markdown 笔记。手机同步及图片/PDF 原件同步不计入首版验收；若用户需要，应在实现前扩充设计。
